# C++ 语言基础的教学顺序与边界

## 类型与变量的教学边界

### 为什么先建立值与类型的关系

初学者真正需要先解决的是“程序怎样保存和改变一份数据”，不是记住所有类型的大小和转换规则。页面先让读者创建几个有意义的变量，再说明类型决定可表示的值、允许的操作和内存解释。

首版只覆盖 `int`、`double`、`bool`、`char` 和 `std::string` 的日常用法。整数宽度、溢出、浮点精度和字符编码留到相应主题，不与基础入门同时展开。

### 初始化、赋值和作用域

初始化与赋值必须作为两种动作介绍：前者在创建变量时确定初始值，后者修改已有变量的值。变量从声明处进入作用域，离开代码块后名字不可再用；这解释了为什么局部变量不能在花括号外访问。

作用域示例应通过“变量在块内可见、块外编译失败”建立边界。不要把生命周期、析构顺序和内存布局提前塞进同页，否则读者无法判断当前学习中心。

### auto 的引入边界

`auto` 是编译期类型推断，不是动态类型，也不会让变量在运行期改变类型。入门阶段只在初始化表达式已经清楚表达类型时使用，例如 `auto score = 95.5;`，避免为了少写字隐藏接口意图。

## 常量与不可变值

### 为什么先讲 const

`const` 解决的是“这个值不应通过该名字被修改”。先讲命名常量对可读性的帮助，再讲必须在创建时初始化、后续赋值会被编译器拒绝。这样读者先获得设计意图，再理解语言限制。

### constexpr 的推迟边界

`constexpr` 适合编译期可确定的值。基础页只保留一个尺寸或比例的短例子，说明它比 `const` 更强调编译期可计算性；模板、常量表达式和编译期求值细节留到后续主题。

## 百章语言路线

### 分页与依赖

语言基础按“数据 → 运算 → 控制 → 函数 → 复合数据 → 自定义类型”推进。每章只依赖前文已经引入的名字和心理模型，新章节通过任务矩阵登记前置、正文和示例。

### 变化点与验证

每个语言概念至少有一个可观察结果：输出值、编译失败或运行时行为变化。后续扩展示例时一次只增加一个变化点，并把结果与前面已经验证的行为对照。
