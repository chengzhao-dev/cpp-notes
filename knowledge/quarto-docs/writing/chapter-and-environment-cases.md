# C++ 章节与开发环境写作案例

## C++ 章节的最小学习路径

引言交代当前问题与完成结果，按“上一章结果 → 本章动作路径 → 最终验收”三件事推进，一句话只做一个动作，工具名和文件名留在第一次用到它的任务里。正文先建立概念模型，再给最小示例、运行或构建命令、成功判据和必要的常见错误。回顾只总结结果、验证方式和下一主题。页面通用块序列以 `cpp-quarto-chapter-pattern-v1` 为准。

```text
上一章已经安装好编译器和构建工具。
本章以仓库中的完整示例工程为起点，先查看工程文件结构，再分别通过 g++ 命令行和 CMake 构建 Hello, World! 示例程序。
运行生成的可执行文件并看到 Hello, World! 后，就完成了本章的实践目标。
```

导语按“上一章结果 → 本章动作路径 → 可观察验收”组织。用“示例程序”明确验收对象，不用“这个程序”或“本章就完成了”这类模糊指代。`g++` 是编译器命令，`CMake` 是构建系统，二者通过“分别通过”连接，不写成同一层级的工具。

规则型内容采用“建议、原因、正例、边界、验证”。例如介绍智能指针时，先说明所有权问题，再展示最小的 `std::unique_ptr` 示例，循环引用和 `std::weak_ptr` 放入后续边界，而非首次示例。

## Windows 与 WSL2 环境

环境章节按“Windows 宿主、WSL2 Linux 发行版、编辑器、构建工具”介绍。环境基线只在本章展开，后续 C++ 章节链接回环境章并声明新增前提。插件、编译数据库和高级调试选项不进入主线。

不要用多组 `--version` 命令替代真实任务。安装完成后直接编译最小程序。失败时在 FAQ 中按症状提供诊断命令和成功判据。

## 终端命令展示

Linux 或 WSL 中的命令使用 `bash` 代码块。PowerShell 使用 `powershell` 代码块。连续、顺序敏感的命令放入代码块。一两条无上下文短命令放在正文。命令块只放可执行命令，输出使用紧邻的 `text` 块。命令、说明与输出如何排布，以 `quarto-docs` 的 terminal-validation 规则为唯一出处，本文件不复述细则。

## 工程展示

展示工程前从磁盘确认目录树。目录树只包含当前任务需要的源码、构建文件和关键产物。不展示缓存目录。目录树、代码块、构建命令和生成结果必须使用相同文件名。

示例源码中的行前注释承担局部职责。正文不逐行翻译注释，只补充代码无法直接说明的前提、因果、边界和验证。

目录树的根行应标出示例工程根目录，行尾注释统一写成“路径 + 用途或性质 + 必要提醒”。例如 `build/` 使用“CMake/Ninja 构建输出目录，请勿手动修改”，`compile_commands.json` 使用“供 clangd 等工具读取的编译数据库”。目录树中已经说明的职责不在树后重复展开。

CMake 任务可以在同一 `##` 下分为“配置并构建”和“用脚本一键配置、构建并运行”两个 `###`。脚本是构建任务的快捷路径，不应在目录层级上与 CMake 并列。命令块后紧跟可观察结果，FAQ 只按症状给出回到成功路径的动作。

## 正确流程与诊断说明

教程正文默认沿正确流程推进。编译器或构建工具出现 warning/error 时，先根据文件名、行号和原因修复。不要把一串故障分支夹进首次成功路径。需要保留的诊断内容放到专门排查章节，或用一个合理标题的短 callout 说明本章最重要的问题。编译成功判据、警告策略和选项职责可以写进对应 CMake、C++ 或 Shell 代码块的原生注释。
