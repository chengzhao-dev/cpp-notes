# 教学正文的页面块序列与职责边界

## 块序列固定为五段的原因

读者在正文里依次进行三种不同的认知活动：确认自己来对了地方、完成一个可验证的动作、确认自己获得了什么。五段各服务一种活动，顺序由「读者先要知道什么才能看懂下一步」决定，而不是由作者手头材料的顺序决定。

```text
引言 → 可选概览或结构 → 任务序列 → 常见错误 → 本章回顾
```

- 引言建立动机与目标，回答为什么要读这一章。
- 概览或结构只在读者需要先看静态对象或路线时出现，让后面的操作有落点。
- 任务序列是主体，每段推进一个可独立验证的动作。
- 常见错误服务失败后回来的读者，先让他定位并回到成功路径。
- 本章回顾最后让成功的读者确认能力、思考关键问题并看到下一步。

打乱顺序的代价是可观察的：把回顾挪到操作之前，读者不知道自己在等什么。把失败分支插进任务序列，成功与失败路径交替出现，读者无法判断当前处在哪个状态。常见错误放在回顾之前，是因为读者只有已经跑通主线后才会顺序阅读回顾；出现故障时会倒回来查找，此时错误分支应比总结更先到达。

## 引言的职责边界

引言同时承担三件事：承接上一章的结果、说明本章要解决的具体问题、交代读者将要获得的整体认识。超出这三件事的内容会推迟读者第一次行动的时间。

- 前置条件属于上一章的回顾或本章第一个任务的开头，写进引言会把读者引向他此刻还不需要的信息，也会与后面的任务步骤重复。
- 引言用普通段落承载动机、范围和结果，不放 Callout；提示框在开头出现会把视觉重心从任务本身移开。
- 后续章节的命令、系统要求与完成结果不出现在引言：读者无法验证，且后章一旦调整就形成事实错误。引言只解释“为什么开始”和“整体由哪些部分组成”。
- 引言不解释术语。术语在第一次真正使用它的任务里给出中文名称与英文检索词。
- 需要读者先看到「做成是什么样」时，给出预期输出而不是实现细节。
- 首个 C++ 程序的引言链接到完整、可直接打开的示例工程。源码细节放在独立的源码阅读任务中，不把单个文件当作章节入口。

## 概念块与任务块的二级标题分层

任务粒度的判定标准是：任务结束时存在一个读者能自己复述的检查动作。如果结束时只是「读完了解释」，这段应该并入相邻任务。反过来，一个 `##` 只承担一个可验证结果，标题写成宽泛主题时读者无法判断这一节要做到什么程度才算完。小节内部如何保持单一主线见 `cpp-quarto-section-focus-density-v1`。

### 新手段落的最小骨架

面向没有前置概念的读者时，每个任务优先按“目标 → 动作 → 结果”组织。目标只说明这一步要得到什么，动作只保留完成目标所需的最少操作，结果给出一个能观察或复述的成功判据。前置条件和失败分支分别放在动作之前和成功路径之后，避免一个段落同时解释背景、步骤和排错。

段落之间用因果关系连接，而不是用同义句重复中心。若一个段落出现两个以上独立动作，或读者无法指出本段结束时要检查什么，就拆成列表或相邻任务。

### 任务内部的递进

概念 → 最小示例 → 操作 → 验证 → 边界。先让读者看到行为，再解释足以理解该行为的规则。完整规则推迟到读者确实需要它的时候。先给规则后给示例时，读者会把第一次阅读用来记忆而不是理解。

### 变化点

扩展同一个示例时一次只引入一个新的语言规则或工程约束。同时改变两件事，读者无法把观察到的差异归因到其中任何一件，验证就失去反馈价值。

### 何时再分层

一个任务同时需要概念、多个操作阶段和独立验证时才切出更小的标题。只有一两句话的内容并入相邻任务。为凑层级增加的标题会让右侧目录变成噪声。

## 环境章与构建章的骨架

环境章与构建章需要不同的稳定骨架，是因为前者先建立可运行环境，后者要在同一工程上比较构建路径。具体骨架与主题顺序归 `cpp-chapter-writing` reference；本文件只解释为什么概念块、任务块和验收位置不能平铺。
## 验证与常见错误的分工

两块都在末尾，顺序依据是它们服务的读者状态不同。

- 常见错误服务失败后回来的读者：每个症状使用 `###`，给定位命令和回到成功路径的动作。
- 本章回顾服务已经成功的读者：总结获得的能力、提出关键问题并给出下一入口。

常见错误与回顾服务不同状态的读者，因此顺序不能互换。具体故障结构和回顾格式分别归 `cpp-quarto-troubleshooting-flow-v1` 与 `quarto-docs` 的章节写作 reference。

## 回顾答案为什么就地折叠

回顾题是读者先自行回答、再对照结论的自测环节。答案默认收起可以保留回忆和判断过程，点击对应问题后的“查看答案”即可核对，不把阅读顺序提前变成答案记忆。

答案紧跟问题，是为了让读者在核对时同时看到条件和结论，不必在章末寻找对应关系。答案集中到单独区域后，问题与解释会形成两套编号或两跳导航，回顾就从自测退化成答案列表。

使用原生 `<details>/<summary>` 不需要额外 JavaScript，键盘可以直接操作，也没有 `##` 标题进入右侧目录。答案仍只使用本章已经讲过的概念；需要引入新知识时，应改写成正文任务或后续章节内容。

## 元素选择的判定依据

元素由信息之间的关系决定，视觉偏好不构成理由。列表、表格、代码块、提示框和源码引用的具体选型归 `authoring` 与 `writing-style-core` reference；这里只保留判断依据，不维护第二套元素表。

同一类信息该放哪个元素之外，还有「密度」这一维：盒子过多会把正文挤成图注，成因与收束方式见标识 `cpp-quarto-section-focus-density-v1` 的知识文件。

## 块序列跨多个页面时如何连接

块序列描述单页内部的顺序，不能整条套到章节集合上：教程集合里排第一的页面承担的是入口职责而不是概述职责，它的页面形状由标识 `cpp-quarto-landing-pattern-v1` 的知识文件决定。

判断依据是读者当前要做的动作。需要他先做选择时用入口与卡片页，他已经确定要完成某个任务时用教学正文。同一份内容出现在两类页面上时，只有正文那一处承担可验证任务，入口那一处退化成定位与下一步。

## 与其他知识文件的分界

本文件只回答页面由哪些块组成、每块的职责边界和顺序依据。段落、句式与措辞案例见标识 `cpp-quarto-chinese-style-v1` 的知识文件。环境、命令与工程展示案例见标识 `cpp-quarto-chapter-environment-v1` 的知识文件。渲染与输出取值见标识 `cpp-tooling-quarto-render-v2` 与 `cpp-tooling-quarto-html-v2` 的知识文件。入口与卡片页的组织见标识 `cpp-quarto-landing-pattern-v1` 的知识文件。
