# 技术文档行内代码标记边界

## 反引号标记什么

反引号的作用是告诉读者“这段文字需要逐字识别或复制”。因此命令、工具、参数、文件名、路径、配置键、API、标识符和包名应统一标记，例如 `clang++`、`clangd`、`lldb`、`CMake` 和 `CMakeLists.txt`。

## 普通名称不自动标记

Ubuntu、Windows 和 VS Code 作为平台或产品名称时属于自然语言，不必加反引号。当它们出现在命令、路径或精确标识中时再标记。链接文本直接使用链接，不用反引号包住链接地址。

## 标题与导航保持单一字体

标题和导航文本属于连续扫读区域。若其中混用反引号，渲染器会把个别词切换成等宽代码字体，同一层级的中英文和工具名就会出现不同的字面、字重与节奏，侧边栏尤其容易显得断裂。标题中的技术名词直接写普通文字，例如“用 CMake 构建程序”，正文再用反引号标记需要逐字识别的 `CMake`。这样保留正文的技术精度，也不让导航承担代码标记职责。

## 行内标记与链接两侧的间距

行内代码和链接标签本身是矩形边界，它们与相邻汉字之间的空格由**边界内侧那个可见字符**决定，而不是由标记类型决定。标签内以英文字母、数字、`.`、`_` 或反引号开头时，这串拉丁字符与后面的汉字会黏成一整串，读者扫读时要先把整串重新切词才能定位链接，因此需要一个空格断开。标签以汉字开头时，方块字与前后汉字天然等宽对齐，插进去的空格反而制造一处假断句，把一条完整的链接文字劈成两截。

判定只看首尾，不看标签长度和中间内容，读者因此可以机械复现：左括号前看标签第一个字符，右括号后看标签最后一个字符，中间的空格交给“中英文之间留空格”的通用规则。全角标点自带视觉留白，紧跟它之后不再补空格。

标签内不再套反引号，是因为链接文字本身已经是可点击标识，双重标记既不增加识别信息，又让行内代码的边界判定失去唯一基准，各渲染器对标签内高亮的处理还不一致。

## 一致性是可读性约束

同一章节中同一对象的标记方式必须一致。只给部分工具加反引号会让新手误以为标记本身代表不同类别，增加扫描和复制命令时的判断成本。写作 skill 的检查器负责发现关键工具的漏标记。本文件记录判断依据。

## 连续句中的行内代码密度

行内代码标记准确，不等于一段话可以连续切换普通文字与标记。命令、输出和路径密集出现时，读者需要不断重置扫读节奏，中心意思会被标记边界切碎。处理方式是保留那些确实需要逐字识别的标识，再把不同对象和判断拆成完整句子，让每句只承担一个观察结果。

例如，原句连续用标记串起输出、产物和构建工具，读者不容易判断哪里是结果、哪里是解释。改写后先说明终端输出代表程序运行成功，再说明工程目录中的产物代表源码已转换，最后引入下一节的构建工具。反引号数量可以减少，但命令、输出、路径和工具等精确标识仍必须保留。
