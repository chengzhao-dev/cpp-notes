# 中文技术写作的段落与措辞案例

## 段落与代码块闭环

一个段落只推进一个对象：说明条件、执行动作、给出结果，再进入下一步。代码块前说明为什么执行，代码块后说明看到什么算成功。

环境示例不要在一句话中同时引入 Windows、WSL2、Ubuntu、编辑器和构建工具。先说明宿主与 Linux 环境的关系，再介绍当前步骤需要的工具。

```text
代码块前：进入示例目录，准备编译 main.cpp。
代码块后：成功后生成可执行文件；下一步运行它。
```

## 长句与连接关系

连接词必须表达真实因果、时序、转折或条件。一个句子出现三个以上动作、多个“并且”或多个括号时拆分，并保留明确主语。

```text
不佳：完成 A 后通过 B 使用 C，并根据 D 判断 E，最后处理 F。
改写：完成 A。接着使用 B 执行 C。根据 D 检查结果；满足条件后处理 F。
```

## 措辞替换

删除不增加信息的“其实”“简单来说”“完全”“非常”“特别”。将“对文件进行修改”改为“修改文件”，将“如果……的话”改为“如果……”或“……时”。

避免“吃透”“讲清”“彻底理解”等无法由正文验证的承诺。系统行为明确主语，例如“API 返回错误”，不要写“错误被返回”。

## 术语节奏

首次出现时给中文名称与英文检索词，后续固定一种称呼。普通概念不用行内代码；命令、路径、文件名、关键字、API 和配置键使用行内代码。多行可复制命令和完整示例使用标明语言的代码块。
