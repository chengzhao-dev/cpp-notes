# Quarto 渲染行为与失效模式

> 本文件记录 Quarto 在渲染、发布与编码环节的实际行为及其根因，是这块领域知识的唯一出处。
> 写给读者的正文约定由 skill 侧 `.cursor/skills/quarto-docs/references/` 承载，不在此重复。
## 项目类型与产物边界

### 输出目录由项目类型决定

1. Book 类型渲染默认输出 `_book/`，website 类型输出 `_site/`，两者不能混用
2. 发布产物的上传路径必须与项目类型匹配，写错会部署一个空目录或旧产物
3. 想在源码仓库里直接看到产物，需要显式改 `output-dir`，这会让产物进入版本控制的视野
4. `quarto render` 默认作用于整个项目，单文件渲染要显式给路径，否则等待时间远超预期

### 资源内嵌的取舍

1. 内嵌资源的目的是产出可单文件分发的 HTML，早期开关名已弃用，同名写法只会出现 deprecated 警告
2. 内嵌选项必须嵌套在输出格式之下而不是项目顶层，放错层级的表现是选项静默失效、产物仍带依赖目录
3. 由 JS 在运行时加载的资源无法内嵌，这是引擎边界而不是配置错误，不要为此反复改配置
4. 单文件分发的收益是可移植，代价是文件体积增大且无法利用浏览器对静态资源的缓存

## 配置解析的行为

### YAML 层级与静默失效

1. Quarto 对未识别的选项不报错，因此「配置没生效」最常见的原因是层级放错而不是拼写错误
2. 缩进与冒号属于同一类高频失误：解析成功但落到别的键上，表现同样是选项无效
3. 站点级配置（导航、侧栏）与格式级配置（目录、主题）分属不同作用域，混放后两边都不生效
4. 判断顺序：先看报错是解析失败还是渲染失败，再核对嵌套层级，最后才怀疑版本
5. 凭记忆写选项会产生幻觉配置；应当查官方参考页确认选项名、默认值与嵌套位置

### 标题与目录的生成规则

1. 右侧目录只收录真实的 Markdown 标题，加粗文本与裸 HTML 标题不会进入
2. 页面标题存在两个来源：前置元数据的 title 与正文顶层 H1，同时写会渲染出两个标题
3. 出现两个标题时还会连带打乱 Book 的章节结构，因为 H1 被当作另一个章节处理
4. 描述字段只在入口页可见，普通章节写了不产生效果，反而增加维护噪音
5. 分隔线紧跟段落会把上一段解析为 setext 二级标题，表现为凭空多出一个大号标题；水平线前后各留空行可避免

## 提示框与代码块的解析边界

### 内置提示框类型是封闭集合

1. 渲染器只识别固定的内置 callout（提示框）类型，未知类型不会产生 callout 节点
2. 未知类型的块会退化成「带标题的普通章节」，副作用是它的标题混进右侧目录
3. 贴在内置类型上的附加类同样被丢弃，因此主题里为自定义类准备的样式永不命中
4. 这类失效是静默的：源文件看着正确，只有渲染产物能暴露，因此需要产物级自检脚本

### 代码包含入不推断语言

1. 代码包含指令只做原样插入，不会根据被插入文件的扩展名推断语言
2. 不在围栏内时插入内容按普通 Markdown 解析：注释符号变成标题、星号与下划线变成强调
3. 结果同时污染页面排版与右侧目录，出现若干假标题
4. 因此引用真实源码必须整体包进带语言名的围栏，没有例外
5. 高亮主题的配置来源应唯一，散落在章节级的覆盖会让同一段代码在不同页面表现不一致

## 编码与路径的失效模式

### 编码链路

1. 仓库统一 UTF-8 无 BOM、LF；违反时最先表现为渲染或 diff 噪音
2. 让系统代码页参与中文读写会把正常中文变成乱码字串，且反向转码无法复原
3. 恢复方式是从版本库的可读版本取回后重做修改，而不是猜测原字符
4. 部分脚本环境写文件默认附带 BOM，需要显式指定无 BOM 编码或改用脚本语言写入
5. 编码检查应作为改动 `.qmd` 或规范文档后的第一步，早于渲染

### 路径与命名

1. 内部资源用相对路径：发布到项目站点后 URL 前缀会变化，绝对 URL 会断
2. 站点托管区分大小写，文件名大小写不一致表现为本地正常、线上 404
3. 路径含非 ASCII 特殊字符时，Windows 侧的过滤器在写索引文件阶段会因无法编码而失败
4. 这类报错的字符名指向的是文件名而不是内容，容易误判为编码问题；确认方式是按字节查看目录名
5. 结论：项目、目录、文件名一律纯 ASCII，连字符只用普通减号
