写出第一个 C++ 程序

完成搭建 WSL2 开发环境后，本章从仓库中的 main.cpp 开始。你会先直接编译并运行它，再用 CMake 保存同一套构建规则。

本章目标

本章结束时，你可以：

  • 查看一个最小 C++ 工程的文件关系。
  • 使用 C++20、-Wall、-Wextra 和 -Werror 编译并运行程序。
  • 编写本章使用的基础 CMakeLists.txt，重复同一构建流程。

直接编译适合确认单个源文件可以工作，CMake 适合保存目标、源文件和构建选项之间的关系。因此本章先使用 g++，再使用 CMake。

查看项目结构

目录树把源码、构建规则和生成结果放在同一个模型中，后面的命令就不再是孤立的文件操作。下面只展示本章会使用的内容，顺序依据示例目录的真实结构。

first-program/
├── build/
│   └── bin/
│       └── app              # 构建生成的可执行文件
├── main.cpp                 # 程序源码
├── CMakeLists.txt           # CMake 构建规则
└── build-and-run.sh         # 一键构建脚本

配置和构建完成后，build/bin/app 才会出现。build/ 中的缓存、日志、对象文件和其他 CMake 生成物不属于本章重点。接下来从 main.cpp 开始。

编写并运行程序

查看源码

下面直接引用仓库中的完整 main.cpp。确认源码后，再执行编译命令：

// 引入标准输出流。
#include <iostream>

int main() {
  // 输出程序运行结果。
  std::cout << "Hello, World!\n";

  // 返回 0 表示程序正常结束。
  return 0;
}

编译并运行

在 Ubuntu 终端中创建输出目录，再用 g++ 按 C++20 标准编译。下面的命令会把可执行文件写入 build/bin/：

# 创建可执行文件的输出目录
mkdir -p build/bin

# 编译源码并输出 app
g++ -std=c++20 -Wall -Wextra -Werror main.cpp -o build/bin/app

编译成功后，进入输出目录运行程序。当前示例的预期结果是 Hello, World!：

$ cd build/bin
$ ./app
Hello, World!

看到 Hello, World!，说明当前源文件已经完成编译、链接和运行。

提示

编译通过只说明当前代码满足编译器要求。保留警告选项可以更早发现未初始化和类型不匹配等问题。

使用 CMake 构建

查看构建规则

直接编译适合确认单个源文件可以工作。把相同的标准和警告选项写进 CMakeLists.txt 后，可以用同一套规则重复构建当前程序。

# 要求使用支持当前项目语法的 CMake 版本。
cmake_minimum_required(VERSION 3.31)

# 声明项目名称，并启用 C++ 语言支持。
project(first-program LANGUAGES CXX)

# 使用 C++20，并要求构建工具遵守该标准。
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# 将可执行文件集中输出到 build/bin，便于查找运行结果。
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)

# 从 main.cpp 构建名为 app 的可执行文件。
add_executable(app main.cpp)

# 启用常用警告，并将警告视为构建错误。
target_compile_options(app PRIVATE -Wall -Wextra -Werror)

配置并构建

在示例目录中先配置，再构建 app 目标。两条命令应依次执行：

# 生成 build/ 中的构建文件
cmake -S . -B build

# 构建 app 目标
cmake --build build

构建完成后，app 会写入 build/bin/。示例还提供一键脚本，适合重复执行配置、构建和运行流程：

# 在示例目录中运行完整流程
bash build-and-run.sh

脚本会调用 CMake，随后运行 build/bin/app。如果任一步失败，脚本会停止并保留错误信息。

#!/usr/bin/env bash
# 一键配置、构建并运行当前 CMake 示例。
# 用法：在项目根目录运行 bash build-and-run.sh。
# 配置阶段会生成构建所需的辅助文件。

# 命令失败、未定义变量或管道出错时停止脚本。
set -euo pipefail

# 无论从哪里调用，都先切换到脚本所在的项目目录。
cd "$(dirname "$0")"

# 将生成物集中到 build/，避免污染源码目录。
BUILD_DIR="build"
BIN_DIR="$BUILD_DIR/bin"
TARGET="app"

# 保存完整构建参数，便于开发工具读取当前工程配置。
printf '\n==> 配置\n\n'
cmake -S . -B "$BUILD_DIR" -DCMAKE_EXPORT_COMPILE_COMMANDS=ON

# 构建 CMakeLists.txt 声明的目标。
printf '\n==> 构建\n\n'
cmake --build "$BUILD_DIR"

# 可执行文件统一放在 build/bin，和中间文件分开。
printf '\n==> 运行\n\n'
cd "$BIN_DIR"
"./$TARGET"
注意

CMake 负责生成构建文件，实际编译仍由底层构建工具完成。它把目标、源文件和选项保存为可重复执行的规则。

常见问题

编译器命令不可用

如果提示找不到 g++，先运行版本命令确认工具状态：

# 检查 g++ 是否可以调用
g++ --version

如果命令仍然报错，再回到搭建 WSL2 开发环境重新安装 build-essential。

构建目录需要重新生成

如果 CMake 使用了旧编译器或旧选项，可以删除可重建的 build/，再重新配置：

# 删除可重建的 CMake 输出
rm -rf build

# 重新配置并构建项目
cmake -S . -B build
cmake --build build

删除 build/ 不会影响 main.cpp、CMakeLists.txt 和 build-and-run.sh。
