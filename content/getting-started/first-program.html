写出第一个 C++ 程序

上一章已经准备好 Linux 开发环境。先打开完整示例工程 first-program，并进入工程根目录。

Hello, World! 是最小的 C++ 程序之一。它只做一件事，把一行文字输出到终端。下面先认识工程文件和源码，再分别用 clang++ 和 CMake 构建它。

认识示例程序

本章会用到下面三个文件。编辑器配置不会影响本章的构建过程，因此先不展开。

工程目录
first-program/
├── CMakeLists.txt    # 构建规则
├── main.cpp          # 程序源码
└── build-and-run.sh  # 一键构建并运行

main.cpp 是程序入口，CMakeLists.txt 告诉 CMake 怎样构建程序。

main.cpp
// 引入标准输出流。
#include <iostream>

int main() {
  // 输出程序运行结果。
  std::cout << "Hello, World!\n";

  // 返回 0 表示程序正常结束。
  return 0;
}

用 clang++ 构建

clang++ 是编译器命令。它读取源码，生成可以直接运行的程序。在工程根目录执行下面的命令。

Ubuntu Bash（工程根目录）
# 创建用于存放可执行文件的目录
mkdir -p build/bin

# 使用 libc++ 编译并链接 C++20 程序
clang++ -std=c++20 -stdlib=libc++ -Wall -Wextra -Werror main.cpp -o build/bin/app

# 运行刚生成的可执行文件
./build/bin/app

程序输出如下。

输出
Hello, World!

看到 Hello, World!，说明程序已经运行。build/bin/app 是刚生成的可执行文件。

注意关键选项
  • -std=c++20 选择 C++20 语言标准。
  • -stdlib=libc++ 选择 LLVM 提供的 C++ 标准库。
  • -Wall -Wextra -Werror 打开常见警告，并让警告阻止构建。
  • -o build/bin/app 指定可执行文件的位置。

用 CMake 构建

CMake 读取 CMakeLists.txt，生成构建规则。Ninja 再执行这些规则，编译源码并生成程序。

CMakeLists.txt
# 低于此版本时配置阶段直接报错，不做兼容回退。
cmake_minimum_required(VERSION 3.31)

# 声明项目名称，并启用 C++ 语言支持。
project(first-program LANGUAGES CXX)

# 与 clang++ 直编命令的 -std=c++20 保持一致。省略会回到编译器默认标准。
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# 对应 clang++ 的 -o build/bin/app，统一把可执行文件放进 build/bin。
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)

# 导出编译数据库，让 clangd 读到与实际构建一致的编译参数。
# 开启后配置阶段会生成 build/compile_commands.json。
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)

# 从 main.cpp 构建名为 app 的可执行文件。
add_executable(app main.cpp)

# -stdlib=libc++ 选择 LLVM C++ 标准库，-Wall -Wextra 打开常用警告，
# -Werror 把警告升级为错误。链接阶段沿用同一个标准库。
# 编译器没有输出表示编译和链接成功。出现 warning/error 时，
# 先按文件名、行号和原因修复。编译通过不代表程序逻辑正确。
target_compile_options(app PRIVATE -stdlib=libc++ -Wall -Wextra -Werror)
target_link_options(app PRIVATE -stdlib=libc++)

先让 CMake 在 build/ 中生成 Ninja 规则。

Ubuntu Bash（工程根目录）
# 配置 CMake 工程并选择 clang++ 与 Ninja
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=clang++

配置成功后，用 CMake 调用 Ninja 完成构建。

Ubuntu Bash（工程根目录）
# 按生成的规则编译并链接
cmake --build build

构建完成后，运行生成的程序。

Ubuntu Bash（工程根目录）
./build/bin/app

输出如下：

输出
Hello, World!

看到 Hello, World!，说明 CMake 配置、Ninja 构建和程序运行都已完成。

使用一键脚本

build-and-run.sh 把刚才的配置、构建和运行命令串在一起。

build-and-run.sh
#!/usr/bin/env bash
# 一键配置、构建并运行当前 CMake 示例。
# 在项目目录中运行 bash build-and-run.sh
#
# 脚本依次完成配置、构建和运行。
# CMakeLists.txt 统一 C++ 标准、警告策略和可执行文件输出目录。

# 命令失败、使用未定义变量或管道出错时停止脚本。
set -euo pipefail

# 无论从哪里调用，都先切换到脚本所在的项目目录。
project_dir="$(cd "$(dirname "$0")" && pwd)"
cd "$project_dir"

# 构建目录与目标名与 CMakeLists.txt 保持一致。
build_dir="build"
target="app"

# 配置 clang++ 与 Ninja Debug 构建
printf '\n==> 配置\n\n'
cmake -S . -B "$build_dir" -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=clang++

# 构建 CMakeLists.txt 中声明的目标。
printf '\n==> 构建\n\n'
cmake --build "$build_dir"

# 运行构建结果
printf '\n==> 运行\n\n'
"$build_dir/bin/$target"

在工程根目录执行下面的命令。

Ubuntu Bash（工程根目录）
# 一键完成配置、构建并运行
bash build-and-run.sh

脚本会依次完成配置、构建和运行。最后看到 Hello, World!，说明流程正常结束。

选择构建方式

两条路径跑通后，可以按工程规模选择：

  • 单个源文件：用 clang++ 直接编译，命令最短，适合第一次验证。
  • 多文件或多目标工程：用 CMake 管理构建规则，让 Ninja 执行编译和链接。

后续示例默认使用 CMake。build-and-run.sh 只是把前面的配置、构建和运行命令放在一起。

常见错误

缺少构建工具

在工程根目录运行命令时提示找不到 clang++、cmake 或 ninja。

  1. 定位缺失工具

    Ubuntu Bash（工程根目录）
    # 检查编译器、CMake 和 Ninja 是否可用
command -v clang++ cmake ninja

    command -v 为每个已安装的工具打印路径，缺失的名字不打印任何内容。

  2. 安装缺失工具

    执行 sudo apt update，再按安装 C++ 工具链重新安装整套工具。

  3. 验证安装

    再次执行定位命令，确认 clang++、cmake 和 ninja 都输出路径。

    Ubuntu Bash（工程根目录）
    # 重新检查编译器、CMake 和 Ninja
command -v clang++ cmake ninja

本章回顾

本章用同一个 Hello, World! 走通了直接编译和 CMake 构建两条路径。可以思考以下问题：

  1. main.cpp 从源码到终端输出，中间经过哪些步骤？

    查看答案

    从 main.cpp 的源码到终端显示输出，整个过程依次经过以下四个步骤：

    1. 在终端执行 clang++ 命令，启动编译器。
    2. clang++ 编译并链接 main.cpp，生成 build/bin/app。
    3. 在终端运行 build/bin/app，操作系统加载并执行这个文件。
    4. 程序把 Hello, World! 写入标准输出，终端显示这行文本。

  2. 单个源文件为什么可以直接使用 clang++，代码变多后为什么要使用 CMake？

    查看答案

    单文件程序直接使用 clang++ 时，命令最短，适合快速验证。源文件和构建目标增多后，手写命令难以维护。此时，CMake 负责描述构建规则，Ninja 负责执行规则并支持增量构建。
