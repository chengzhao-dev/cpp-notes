搭建 WSL2 开发环境

后续命令要在 Linux 中执行，Windows 不能直接运行它们。WSL2 让 Windows 可以使用 Linux 环境，Ubuntu 是这个环境里使用的 Linux 系统。本章安装 Ubuntu，并准备编译、运行和调试 C++ 程序所需的工具。

准备 Linux 开发环境

安装 WSL2 和 Ubuntu

以管理员身份打开 Windows PowerShell，执行下面的命令安装 WSL2 和默认的 Ubuntu。Linux 有多个发行版，发行版可以理解为包含系统和常用工具的完整版本。

PowerShell（管理员）
# 安装 WSL2 和默认的 Ubuntu 发行版
wsl --install

命令执行完成后，按提示重启 Windows，让新启用的 WSL2 组件生效。重启后首次启动 Ubuntu，按提示创建 Linux 用户名和密码。输入密码时不会显示字符，这是正常现象。

创建账号后，终端会显示提示符。请对照下面的格式，确认是否已经进入 Ubuntu，并了解后续命令的执行位置。

注意提示符与终端范围

看到类似 user@host:~$ 的提示符，就说明已经进入 Ubuntu。后续 bash 命令都在这个终端中执行。

  • user 是用户名。
  • host 是电脑名称。
  • ~ 是当前用户的主目录。

安装其他发行版

本节只用于安装 Ubuntu 之外的 Linux 系统。继续使用默认 Ubuntu 时，可以跳过本节。

要安装其他发行版时，先执行下面的命令查看 WSL 当前提供的名称。

PowerShell
# 查看可安装的发行版名称
wsl --list --online

从输出中复制目标发行版的名称，原样替换安装命令中的 <发行版名称>，再执行下面的命令。

PowerShell
# 安装指定发行版
wsl --install -d <发行版名称>

安装 C++ 工具链

进入 Ubuntu 终端后，执行下面的命令。软件源是 Ubuntu 下载软件的位置，先更新软件包列表，再安装 C++ 工具链。工具链是编译器、构建工具、调试器和语言服务的统称。

Ubuntu Bash
# 更新软件包索引
sudo apt update

# 升级已安装的软件包
sudo apt upgrade -y

# 安装 Clang/LLVM 编译、构建、调试和语言服务工具
sudo apt install -y clang clangd llvm lldb libc++-dev libc++abi-dev cmake ninja-build
提示下载较慢时再更换软件源

更换软件源只改变软件从哪里下载，不会改变 Ubuntu 版本。下载较慢时，按清华大学开源软件镜像站的 Ubuntu 软件源帮助完成配置，再重新执行本节命令。

常见错误

虚拟机平台未启用

执行 wsl --install 后提示“虚拟机平台未启用”，安装无法继续。

  1. 定位缺失项

    在电脑启动设置中确认 CPU 虚拟化已经开启。再检查 Windows 功能列表中的“虚拟机平台”和“适用于 Linux 的 Windows 子系统”是否已经启用。

  2. 启用缺失项并重启

    在“启用或关闭 Windows 功能”中启用缺少的项目。如果电脑启动设置中尚未开启 CPU 虚拟化，也先将其开启，再重启 Windows。

  3. 重新安装并验证

    以管理员身份再次执行 wsl --install。首次启动 Ubuntu 后出现 Linux 提示符，就回到安装 WSL2 和 Ubuntu 继续完成账号创建。

找不到命令

在 Ubuntu 中运行某个 C++ 工具时提示 command not found。

  1. 定位缺失工具

    执行下面的命令，查看哪些工具没有输出路径。

    Ubuntu Bash
    # 检查工具是否已经安装
command -v clang++ clangd lldb cmake ninja

  2. 安装缺失工具

    缺少工具时，先执行 sudo apt update，再按安装 C++ 工具链 补齐对应软件包。

  3. 验证安装

    再次执行定位命令，确认每个工具都输出路径。

    Ubuntu Bash
    # 重新检查工具是否已经安装
command -v clang++ clangd lldb cmake ninja

软件源更新失败

执行 sudo apt update 时出现下载失败或软件源不可用等错误。按下面的顺序找到失败来源，改用可用软件源，再重新验证。

  1. 定位失败来源

    确认命令在 Ubuntu 终端中执行，并记录错误输出中的软件源地址和 Ubuntu 版本。

  2. 配置可用软件源

    按清华大学 Ubuntu 镜像使用帮助为当前 Ubuntu 版本配置软件源。

  3. 验证更新结果

    Ubuntu Bash
    sudo apt update

    命令正常结束且不再出现软件源错误，说明软件源已经恢复。回到安装 C++ 工具链 继续操作。
