# 对比与解读示例 / 案例（writing-style.md 配套）

本文件是 `writing-style.md`「对比型知识点（相似概念先分家）」与「代码与正文分工」中代码后逐项解读、失败路径预判两条的 before/after 案例库。规则见 `../writing-style.md`。

## 概念对比（差异设问 + 双条结论 + 代码）

反面（一段长文纠缠两个概念的异同，结论埋在段中）：

~~~markdown
# 避免
在 C++ 中 `new` 和 `malloc` 都可以分配堆内存。`new` 会调用构造函数并且是类型安全的，而 `malloc` 只分配原始内存，返回 void 指针，还需要手动计算大小，两者虽然功能相似但是用法不同，很多初学者都搞不清楚应该用哪一个。
~~~

正面（先差异设问，再双条结论列表，随后代码印证）：

~~~markdown
# 推荐
`new` 和 `malloc` 都能在堆上分配内存，功能相似容易混淆，但两者在初始化与返回类型上有较大不同。

- `new` 的作用是按类型分配内存并调用构造函数，返回该类型的指针；
- `malloc` 的作用是只分配指定字节数的原始内存，返回 `void*`，不会运行任何构造代码；

如下代码展示了两者在返回类型与初始化行为上的差异：

```cpp
Widget* p1 = new Widget(42);
void* p2 = std::malloc(sizeof(Widget));
```
~~~

要点：设问句先承认「相似、易混淆」，双条列表把结论分家（每条「A 的作用是…」一句收住），代码随后印证；同一目标的两种做法（方法 1/方法 2）不走此范式，见 cases/supplementary.md。

## 代码后逐项解读（编号列表对应产出/分支）

反面（代码块后用长段复述各行输出）：

~~~markdown
# 避免
上面的输出中，第一段显示了 g++ 的版本是 13.2.0，第二段显示了 cmake 的版本是 3.28.3，两个版本号分别对应两个不同的工具……
~~~

正面（编号列表逐条对应，项首带代码名）：

~~~markdown
# 推荐
1. 首行输出来自 `g++`，13.2.0 就是编译器版本；
2. 首行输出来自 `cmake`，3.28.3 就是构建系统版本；
~~~

要点：解读点 ≥2 个（产出、分支、条件）时编号列表逐条对应；单个解读点留在正文句子即可，不为凑列表而列表。

## 失败路径预判（成功验证后补一句误区）

反面（只写成功路径，读者踩坑后才知道错在哪）：

~~~markdown
# 避免
看到版本号输出，工具链就验证完毕了。
~~~

正面（成功判据 + 常见误区随文预判）：

~~~markdown
# 推荐
看到版本号输出，工具链就验证完毕了。而如果在 PowerShell 里直接运行 `g++` 提示找不到命令，多半是没进 WSL2 终端，这些工具都装在 Ubuntu 里。
~~~

要点：随文预判与「常见问题」互补——高频、当场就会踩的误区紧贴验证步骤写；低频、多成因的排错才收进 FAQ。

## 设疑揭示（反直觉现象四拍）

反面（直接断言结论，读者没经历困惑，印象不深）：

~~~markdown
# 避免
注意：vector 扩容后原来的迭代器都会失效，不要继续使用。
~~~

正面（输出 → 问句 → 机制 → 正确做法）：

~~~markdown
# 推荐
```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();
v.push_back(4);
std::cout << *it;   // 可能输出垃圾值，也可能崩溃
```

怎么回事？`it` 指向的位置没变，为什么就悬空了？

实际上 `push_back` 容量不足时会换一块更大的内存区域，原来的元素被整体搬走，指向旧内存的 `it` 自然失效。

正确做法是扩容后重新取迭代器，或者一开始就 `reserve` 足够的容量。
~~~

要点：四拍缺一不可——没有问句就没有「原来如此」的落差；机制一句讲透即可，更多细节走前向引用。

## 读输出提示再行动

反面（替读者把输出里的提示抄成新步骤，重复且学不会读输出）：

~~~markdown
# 避免
要取消暂存 CONTRIBUTING.md，请运行 git restore --staged CONTRIBUTING.md。
~~~

正面（指给读者看，让输出当老师）：

~~~markdown
# 推荐
输出里已经提示了怎么做：「use git restore --staged <file>... to unstage」。按提示运行即可取消暂存。
~~~

要点：`git status`、编译器 fix-it 这类输出自带下一步指引时，教会读者先读输出再敲命令；提示过时或含糊时才自己写步骤。
