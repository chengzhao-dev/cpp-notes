# 详略与衔接示例 / 案例（writing-style.md 配套）

本文件是 `writing-style.md`「详略与衔接（该清楚则清楚，该模糊则模糊）」的 before/after 案例库。规则见 `../writing-style.md`。

## 术语突兀 → 就地说清

反面（方法名未解释就甩给读者，前后递进接不上）：

```markdown
# 避免
兼容性最好的是导出再导入，可在任意 WSL2 版本间迁移。以管理员身份打开 PowerShell 后执行：
```

正面（做法直接写进句子，不需要先懂名词）：

```markdown
# 推荐
先导出成备份文件，再导入到新位置。以管理员身份打开 PowerShell 后运行：
```

要点：「导出再导入」对新手是黑盒；展开成「导出成备份文件 → 导入到新位置」，名字不用先教。

## 直陈问题，不拿示例指代

反面（用示例盘符代替问题陈述）：

```markdown
# 避免
C 盘空间紧张时，可整体迁移到 D 盘。
```

正面：

```markdown
# 推荐
系统盘空间不足时，可把 Ubuntu 整体迁移到其他磁盘。
```

要点：说清对象与条件（Ubuntu 装在系统盘、空间不足、迁去其他磁盘）；「C 盘/D 盘」是本机示例，不是所有读者的实际情况，具体盘符交给命令。

## 一般段落不举「例如」

反面（普通叙述里塞具体例子）：

```markdown
# 避免
可整体迁移到 D 盘，例如迁到 D:\ProgramData\WSL\Ubuntu。
```

正面：

```markdown
# 推荐
可整体迁移到其他磁盘。
```

要点：举例留给专门讲解处；这里的目的只是「系统盘紧张可搬家」，路径在命令块里本来就完整。占位符解读（如 `<distro>` 给出 `Ubuntu-24.04`）属专门知识点，允许举例。

## 前向引用一句带过

反面（后文专章的内容当下展开，冲淡本节主线）：

```markdown
# 避免
链接器的工作包括符号解析、重定位、段合并等，每个阶段都有不少细节，比如符号解析要区分强符号与弱符号……
```

正面（一句预告 + 当下够用的最小解释）：

```markdown
# 推荐
链接的完整过程会在后面的章节中详细介绍，这里只需要知道它把库函数的实现接到你的程序上。
```

要点：后文有专章的机制不当下展开；「后面会讲 + 这里只需要知道 X」保住主线，读者拿到够用的心智模型再往下走。

## 验证判据：通用判据 + 代表工具 + 其余同理

反面（逐个工具各写一块「运行 X 看输出」，重复啰嗦）：

~~~markdown
# 避免
装完后运行 g++ --version 看 g++ 是否可用，再运行 cmake --version 看 cmake 是否可用，还要运行 gdb --version 看 gdb 是否可用……
~~~

正面（一句通用判据 + 挑最常用的两个演示 + 尾句兜底）：

~~~markdown
# 推荐
验证方法对每个工具都一样，运行它的 `--version`，输出首行打印出版本号，就说明这个工具可用。工具链里装的工具不止一个，逐个确认不现实，先挑最常用的两个，比如 `g++` 与 `cmake`：

…（`g++`、`cmake` 两个演示块）…

其余工具同理，需要用哪个，就运行哪个的 `--version`。
~~~

要点：「先挑最常用的两个」属代表性验证举例，允许在专门讲解验证的段落点名具体工具；逐块演示只做代表，不为每个工具铺块。
