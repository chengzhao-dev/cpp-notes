# 破坏性告诫示例 / 案例（writing-style.md 配套）

本文件是 `writing-style.md`「callout 句式」中破坏性操作告诫、可恢复边界句、版本锚定 Note 三条的 before/after 案例库。规则见 `../writing-style.md`。

## 破坏性操作告诫（后果 / 除非否则 / 更好做法）

反面（只说危险，不说后果与出路）：

~~~markdown
# 避免
注意：git checkout -- 是危险命令，谨慎使用。
~~~

正面（三件套 + 同命令多形态分级）：

~~~markdown
# 推荐
> 重要：`git checkout -- [file]` 是一个危险的命令，你对那个文件做的任何修改都会消失，它只是用另一个文件把它覆盖了。除非确实清楚不想要那个文件，否则不要使用这个命令。

如果你仍想保留对文件做出的修改，但现在需要撤销，可以先把改动保存到分支里；这些通常是更好的做法。

不加选项地调用 `git reset` 并不危险，它只会修改暂存区域，工作目录里的文件不会被改动。
~~~

要点：危险等级跟着参数形态走，一句话点明哪个形态安全；告诫必须带出路（更好做法指针），光吓唬不给出路，读者只会跳过。

## 可恢复边界句

~~~markdown
# 推荐
在 Git 中任何已提交的东西几乎总是可以恢复的，甚至被删除分支里的提交也能恢复。然而，任何未提交的东西一旦丢失，很可能就再也找不回来了。
~~~

要点：前半句给安心（大胆尝试），后半句划红线（提交是安全点）；两句成对出现，删掉任何一半边界都不完整。

## 版本锚定 Note（章首一次声明）

~~~markdown
# 推荐
> 注意：本章示例在 CMake 3.28 上验证。大部分用法在更早的 3.x 版本同样可用，少数命令的行为可能有差异。
~~~

要点：版本会随时间漂移的主题（编译器、构建系统）在章首用 Note 一次承诺版本与兼容范围；此后各命令不再重复标版本，语言特性例外才用行内标注（「C++20 引入」式）。
