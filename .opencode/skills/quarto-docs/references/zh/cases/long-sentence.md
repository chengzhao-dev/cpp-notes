# 长难句示例 / 案例（writing-style.md 配套）

本文件是 `writing-style.md`「长难句的中心结构」的 before/after 案例库。规则见 `../writing-style.md`。

## 章节引言：散 → 聚

示例（WSL2 环境章引言，先散后聚）：

```markdown
# 散：多动作并列、无中心
欢迎！这一章我们一起来：在 Windows 上用 WSL2 搭一套 Linux 环境，专门用来写 C++。WSL2 是 Windows 里的 Linux 子系统，本章会在它上面安装 Ubuntu 这个 Linux 系统。等环境装好、工具链就位，你就能直接编译、构建和调试自己的程序了。

# 聚：是句 + 它句（两句版）
WSL2 是 Windows 里的 Linux 子系统。本章在 Windows 上用它搭好一套 C++ 开发环境，装好 Ubuntu，并配齐编译、构建与调试工具链。
```

要点：术语定义独立成句（是句），后句用「用它」承接并列动词串（搭好 → 装好 → 配齐）；括号释名塞首句、与首句同义的收束句都删。

## 两类信息拆开（句子或列表）

示例（WSL2 环境章「启动与关闭」启动段）：

```markdown
# 避免：一句塞两类信息（事实 + 方法），逗号串成松散长句
进入 WSL2 后终端停在你启动时的 Windows 目录，要回到固定为 /home/<用户名> 的 Linux 主目录，用 `cd ~`，或一开始就 `wsl ~`。

# 推荐：拆成两句（事实句 + 方法句）；并列提醒类信息也可拆成短列表
进入后终端停在你启动时的 Windows 目录。要回到 Linux 主目录，进入后运行 `cd ~`，或启动时就运行 `wsl ~`。
```

要点：三步合并只适用于同一命题的时序推进；「事实 + 方法」这类两类信息硬合一句就是松散并列——正文语境拆成两句（事实 → 方法，逐字见环境章启动段），列表/提醒语境拆成短列表、每条一句（规则见 `../writing-style.md`「合并的边界」）。单一命题的过渡句仍可用三步合并，不必拆成松散两句、也不必用括号藏信息。

## 章节开头

反面示例（括号释名塞进首句）：

```markdown
本章在 Windows 上用 WSL2（Windows 里的 Linux 子系统）搭好一套装着 Ubuntu 与 C++ 工具链的 Linux 开发环境。
```

正面示例（WSL2 环境章开头，是句 + 它句）：

```markdown
WSL2 是 Windows 里的 Linux 子系统。本章在 Windows 上用它搭好一套 C++ 开发环境，装好 Ubuntu，并配齐编译、构建与调试工具链。
```

要点：定义独立成句后，主句不再被插入语打断；「装好 Ubuntu，并配齐编译、构建与调试工具链」用并列动词串完成推进；不三处重复（结构详见 `../writing-style.md`「长难句的中心结构」与「常用句式库」）。

## 少用破折号 `——` 硬接

反面（用 `——` 硬接解释/补说）：

```markdown
# 避免
`wsl` 提示「不是内部或外部命令」，说明 Windows 的「适用于 Linux 的 Windows 子系统」功能还没打开——系统不认识 `wsl` 这条命令。
```

# 推荐：解释用逗号或句号断开，能拆两句就拆
`wsl` 提示「不是内部或外部命令」，说明 Windows 的「适用于 Linux 的 Windows 子系统」功能还没打开，系统因此不认识 `wsl` 这条命令。

要点：追加说明、同位解释用 `，` 或 `。` 断开，不把 `——` 当「硬接」工具；与「分号克制」同源。

## 少用解释冒号 `：` 硬接

反面（用解释冒号提起展开，后半句被降格为附注）：

```markdown
# 避免
WSL2 是 Windows 里的 Linux 子系统：我们会在其中装好 Ubuntu，再配齐编译、构建与调试工具。
```

正面（解释用句号拆成两句，前后各自成立）：

```markdown
# 推荐
WSL2 是 Windows 里的 Linux 子系统。我们会在其中装好 Ubuntu，再配齐编译、构建与调试工具。
```

一句双冒号（句中解释冒号与句尾引出冒号叠用）：

```markdown
# 避免
装好后在 PowerShell 中用 `wsl --status` 确认：默认分发是 `Ubuntu`、默认版本是 `2`，即表示 WSL2 已装好：
```

```markdown
# 推荐
装好后在 PowerShell 中用 `wsl --status` 确认默认分发是 `Ubuntu`、默认版本是 `2`，即表示 WSL2 已装好：
```

要点：解释冒号把后半句降格为附注，两句各自成立时直接用句号；句中的解释冒号改为动词直连宾语，一句之内冒号至多一个（句尾引出命令块的那个）；冒号只保留三类用法，即标签后（**标签**：、第 X 步：）、引出列表与命令块（命令如下：）、注意块头（注意：）；「看 STATE 一列判断状态：Running 表示…」属标签枚举，保留；与「分号克制」「破折号硬接」同源。

## 逗号分句连贯化

反面（「手段 → 结果」的两个分句用逗号松散并列，读起来像两个碎片）：

```markdown
# 避免
- 装好并启用 WSL2，用 Ubuntu 作为开发环境；
```

正面（用「让」把手段与结果串成一句连贯的话）：

```markdown
# 推荐
- 装好并启用 WSL2，让 Ubuntu 成为开发环境；
```

要点：「A，B。」里的 B 若是 A 的目的或结果，用「让/把/再」等连接词串成一句；真正的排比/对仗并列（如「启动就是…，关闭则是…」）才保留逗号分句。

## 头重脚重中间轻 → 三步平衡（软件源头段）

反例（头重、脚重、中间轻：开场背景铺长，结尾动作也长，唯独「为何换」的递进被压成一句薄条件）：

```markdown
# 避免
Ubuntu 的默认软件源就是官方源 `http://archive.ubuntu.com/ubuntu`，通常无需改动就能正常更新。若你执行更新或下载时明显卡顿，多半是官方源在所在网络偏慢，可换用清华大学开源软件镜像站的 Ubuntu 镜像 `https://mirrors.tuna.tsinghua.edu.cn/ubuntu` 加速。
```

正例（三步平衡：首句点题给结论 → 推进给「何时/为何换」实权重 → 末句落在做法）：

```markdown
# 推荐
Ubuntu 默认软件源就是[官方源](http://archive.ubuntu.com/ubuntu)。只有更新或下载明显卡顿时，才换用[清华大学开源软件镜像站](https://mirrors.tuna.tsinghua.edu.cn/ubuntu)加速，这多半是所在网络访问官方源偏慢导致的。
```

要点：开头（结论）与结尾（动作）都要有分量，但「中间」（依次推进）不能塌成一句轻飘条件，把「何时换、为何换」作为推进主轴给足权重。注：本章软件源段落终稿已合并为单段（默认句 + 「再」例外句 + 出处，见 `adjacent-paragraphs.md`「软件源」案例）；本例保留三步平衡的结构示范，尾注已按「陈述句不带吞吐尾注」删除。

## 安装小节引言：去掉「说明书腔」与「设计理由」

反例（像操作手册罗列顺序 + 加粗规则，还把「为何这样分组」的设计理由写进正文）：

```markdown
# 避免
C++ 开发离不开编译器、构建系统与调试器。下面按「更新索引 → 升级系统 → 分三组安装工具」的顺序装齐。**同厂商或性质相近的工具放在同一条命令里**，既能一次装好，也方便看清每组职责。各组件分工见每条命令后的说明。
```

正例（只讲「做什么、按什么顺序」，设计理由留在规划阶段，不进备忘录正文）：

```markdown
# 推荐
C++ 开发需要编译器、构建系统与调试器，下面按顺序把它们装齐。
```

要点：章节操作引言用「我们/你」口吻、只交代动作与顺序；「同族放同命令」「为何这样分组」属设计方案，不要写进读者照做的正文。
