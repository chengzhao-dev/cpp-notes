# 常见问题示例 / 案例（writing-style.md 配套）

本文件是 `writing-style.md`「常见问题（FAQ / 速查）环节」的格式示例库。规则见 `../writing-style.md`。

- 范例：

```markdown
## 常见问题

**`std::move` 真的会移动对象吗？** 不会，它只是把左值转成右值，真正的移动由移动构造/赋值完成。

**什么时候用 `shared_ptr`？** 仅在多个对象确实需要共享同一份资源、且无法确定谁最后使用时。

## 排错型（症状 → 主旨 → 分情形排查）

写「安装 / 配置踩坑」这类常见问题时，从既有规则提炼：

1. **层级分工**（来自 标题/段落）：`##` 级只写概括性导语（核心框架句 + 指向），**不写具体症状、成因与分情形**；这些全下沉到 `###` 级。后续增删条目只动 `###`，`##` 导语保持稳定。
2. **标题（症状即标题）**：`###` 直接用报错原文或症状，不加引号（如 `### WSL2 提示不是内部或外部命令`）；不硬拼 `/`、结尾不用句号；不概括化稀释症状。
3. **`###` 首段一句归因**：一句话点现象与主要方向（如「多半是安装前提或功能开关的问题，依次排查」），随后进入排查步骤，不在首段枚举具体处置。
4. **排查步骤三段式（作者组织原则）**：① 前提检查（不满足则无法进行）→ ② 功能/配置开关 → ③ 装好后仍出现时的处理；排序只用于组织步骤，正文用「依次排查」带过、不向读者写「按优先级」字样；每条「**名词标签**：动作 + 归因」；`####` 情形小节仅当同一症状确有多个互斥成因需分别展开时才用（前加 `---` 分隔）；**只写亲历情形**，没遇到的不预列。
5. **列表与代码**（来自 列表三步/名词标签加粗）：排查走列表「动作+目的」；命令单独放代码块。
6. **末尾呼应**：块末一句呼应主旨。

### `##` 导语：核心框架句，不提前塞成因

反面（用「坑」且 `##` 级塞具体主旨，冗余）：

```markdown
## 常见问题

安装 WSL2 时最常踩的坑都围绕一件事：**WSL 可选组件没装好**。下面按现象分条排查，遇到对应现象直接对照处理。
```

推荐（`##` 只用核心框架句；「坑」不如「排错场景」准确，成因下沉 `###`）：

```markdown
## 常见问题

下面是安装过程中最常见的排错场景，遇到对应现象时对照处理。
```

### 标题/分段反面一：标题用 `/`、两段堆砌（初稿）

反面（标题用 `/` 拼症状；两段各塞一个情形、无主旨、看着乱）：

```markdown
### wsl 安装没反应 / 命令找不到

若本机已经启用过 WSL 组件，`wsl --install` 只会输出帮助文本、不再执行安装。此时可用 `wsl --list --online` 查看可安装的 Linux 系统，再用 `wsl --install -d <distro>` 安装，例如 `Debian` 或 `Ubuntu-24.04`。

若 `wsl` 命令提示「不是内部或外部命令」，通常是 WSL 可选组件尚未启用，或安装后未重启。请先以**管理员身份**运行 `wsl --install`，若仍无效，在「控制面板 → 程序 → 启用或关闭 Windows 功能」中勾选**虚拟机平台**与**适用于 Linux 的 Windows 子系统**，重启电脑后再试。
```

### `###` 首段与情形反面二：首段枚举具体情形 + 罗列未亲历情形 + 长段堆砌

反面（首段把两种表现写死、还列了未亲历的「情形一」；情形二解释堆成一段，不推荐）：

~~~markdown
### wsl 命令无法正常工作

实际有两种表现，本质却相同——WSL 组件没正确启用：要么命令能跑但 `wsl --install` 只打印帮助，要么连 `wsl` 都提示「不是内部或外部命令」。下面分别处理：

**情形一：命令能跑，但 `wsl --install` 只打印帮助**
本机已启用过 WSL 组件时，`wsl --install` 不再执行安装、只输出帮助文本。改用发行版名显式安装：

```powershell
wsl --list --online
wsl --install -d <distro>   # 例如 Debian 或 Ubuntu-24.04
```

**情形二：输入 `wsl` 提示「不是内部或外部命令」**
通常是组件未启用、或装完没重启。先以**管理员身份**运行 `wsl --install`；仍无效就在「控制面板 → 程序 → 启用或关闭 Windows 功能」中勾选**虚拟机平台**与**适用于 Linux 的 Windows 子系统**，重启后再试。
~~~

### 推荐（症状即标题；首段一句归因；排查步骤三段式；少用 `——`）

~~~markdown
### WSL2 提示不是内部或外部命令

系统不认识 `wsl` 这条命令，多半是安装前提或功能开关的问题，依次排查。

排查步骤：

1. **确认系统版本**：WSL2 需要 Windows 10 版本 2004 及以上，或 Windows 11。版本不满足时无法安装 WSL2，先升级系统。
2. **启用 WSL2 组件**：功能没启用时 `wsl` 命令还不存在。以**管理员身份**运行 `wsl --install`；仍未解决，在「控制面板 → 程序 → 启用或关闭 Windows 功能」勾选**虚拟机平台**与**适用于 Linux 的 Windows 子系统**。
3. **装好后仍报错**：重启电脑让组件生效，再运行一次 `wsl --install`。

排查完成后运行 `wsl --status`，看到「安装 WSL2」第 3 步的输出就说明修复成功。
~~~
```
