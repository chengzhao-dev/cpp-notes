# 百章课程的任务矩阵与分层校验

## 任务矩阵作为单一事实源

### 为什么删除第二份章节表

章节数量增加后，任何生成脚本都会形成第二份状态和路径来源。脚本、矩阵与正文三者一旦漂移，校验成本会先花在同步重复数据，而不是发现真实内容问题。任务矩阵直接维护状态、前置、正文、示例和专项读取，已经足够承担路由职责。

### 磁盘仍是最终判据

矩阵是规划与读写边界，不代替磁盘。`check_task_matrix.py` 仍要检查 done 正文、示例、`_quarto.yml` 注册和前置 ID；`scope.py` 仍要从矩阵反查最小读取集。删除生成器只去掉重复章节表，不删除这些行为契约。

## 校验成本分层

### 内容变更与主题变更

普通正文或语言章节只改变内容，默认校验应覆盖文档结构、示例、任务矩阵和知识召回。主题、Quarto 配置或页面骨架发生变化时，才需要跑全页面、明暗模式和全部视口的布局矩阵。两种改动混在一起时，优先按风险较高的主题矩阵执行。

### 知识分块与摘要

知识库增长后，按文档反复扫描全部 Chunk 会形成文档数与 Chunk 数的乘积成本。构建和摘要阶段应先建立 `doc_id` 索引，再按文档取用 Chunk；索引增量仍以内容哈希为准。这样增加新文档时，成本主要随新增文件和新增 Chunk 增长。

## 增长边界

### 抽样与全量

当页面数量增长到几十或上百时，浏览器检查不应默认对每一页执行所有视口和配色组合。稳定内容按 part 或职责抽样，抽样页面必须包含入口、构建页、库页和语言基础页；主题、布局配置或排版规则变化时再切回全量。

抽样不是新的正确性声明。被抽中的页面必须真实渲染、测量并产生明确结果；跳过的页面要在输出中说明原因，不能用“抽样通过”代替全量主题变更验证。

### 何时升级校验

如果页面模板、导航层级、代码块样式、字体或三栏宽度发生变化，抽样不再足够，必须全量验证。若新增内容反复在同一位置失败，应先修正页面模板或共享检查，而不是把更多页面加入人工清单。
