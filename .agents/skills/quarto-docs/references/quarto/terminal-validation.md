# 终端命令与实测输出

本文件是命令、说明与输出展示细则的唯一出处，其他文件只保留指针，不重复展开。

## 命令与结果的顺序

命令块前分别说明执行环境和前置条件，不把权限、系统版本、命令和结果挤在同一句中。推荐使用以下顺序：

1. 说明先决条件和执行位置。
2. 给出可复制的命令。
3. 展示预期结果或真实输出。
4. 说明成功判据和下一步。

有明确先后关系的动作使用有序列表，并列的系统要求、工具要求和注意事项使用无序列表。每个代码块前用一句正文说明目的，块后只写成功判据或下一步。

## 实测输出

目录、文件名、版本号、工具状态和终端输出应先通过磁盘或命令获取，再写入文档。标记为在 Ubuntu 或 WSL 中运行的只读验证命令，先实际执行，再保留能判断成功的关键行。输出过长时可以筛选版本行、状态行或关键错误，但不能凭空编写结果。

安装、升级和转换发行版等会改变系统状态的命令只展示操作步骤，不在写作过程中重复执行。安装完成后的版本检查可以单独实测并展示结果。环境不可用时只写检查方法，并明确没有实测输出。

不预先编写长段环境校验。逐项运行 `g++ --version`、`cmake --version`、`wsl --status` 之类命令只能证明「此刻命令可调用」，读者已经安装的软件包不会因此变可靠，一旦环境缺失还得重读一遍诊断流程，收益低于成本。安装命令之后直接进入下一步实际操作，报错时由 FAQ 承接诊断。需要展示版本时，把版本信息作为一次实测输出的副产品，例如配置阶段打印的编译器版本。


## 命令、说明与输出三分法

命令块只放能直接复制执行的命令，以及紧贴在命令上方的原生注释。不加 `$ ` 或 `PS>` 提示符，不在命令行末尾追加注释。说明命令用途的段落放在命令块之前，负责详细解释，代码块注释只做一句话定位。输出放在紧随其后的 `text` 块中，命令块与输出块之间只留一个空行。没有结果演示时不添加 `text` 块，多条命令之间同样留一个空行。

标点规则只作用于正文、标题、表格和列表，行内代码与代码块内部照抄真实语法，不做改写。带命令前缀的列表项例外：`- 运行 `wsl --install`；` 之后被反引号闭合的部分属于正文，仍然受规则约束。把多条命令串进一句话，读者无法判断该复制哪一行，应当拆成独立的代码块或独立句子。

按执行环境选择代码块语言：

| 内容 | 代码块 | 约定 |
|---|---|---|
| Linux、WSL 和 Bash 脚本 | `bash` | `#` 注释单独成行，写在被说明命令的正上方。整份脚本的用途注释放在 shebang 与 `set -euo pipefail` 之间 |
| Windows PowerShell | `powershell` | `#` 注释单独成行，写在被说明命令的正上方 |
| 真实输出、目录树 | `text` | 不放命令、`$ ` 或 `PS>`，不启用语言高亮 |

提示符会让读者分不清哪一行能复制：一个 30 行的块里真正要敲的往往只有三行，粘贴带提示符的行到终端还会直接报错。注释单独成行不会产生这个问题，它复制进终端会被 shell 忽略，还能让读者脱离上下文看懂每一行的职责。

```bash
# 安装编译器、构建工具、调试器和静态检查工具
sudo apt install -y build-essential gdb cmake ninja-build clang clang-tidy clang-format
```

命令有输出需要展示时，说明成功判据的正文写在两个块之间，输出进独立的 `text` 块：

```bash
# 查看已安装的 CMake 版本
cmake --version
```

```text
cmake version 4.2.3
```

只有一两条、读者可以直接理解的短命令，例如 `wsl` 和 `wsl ~`，直接放进正文句子。需要区分用途、强调执行顺序或方便复制时，才保留代码块。面向读者的命令使用完整、可读的长选项（例如 `wsl --list --verbose`），不要使用难以记忆的缩写选项。

删除、重建和重新配置分开表达。「某操作不会影响哪些源文件」这类短结论可以使用 Markdown 引用块。命令块后只保留成功判据和下一步，结果不在正文中重复堆叠。代码块中的注释只说明当前操作的职责，不逐行翻译命令，也不引入正文没有讲过的概念。`{{< include /code/... >}}` 引用真实源码文件，这些文件脱离文档单独阅读，注释按常规写法保持简洁明了，不需要遵守上面这套代码块注释密度要求。

正文默认沿正确流程书写，不把“出现 warning/error 后怎么办”夹在成功路径中。发生诊断时先根据输出中的文件名、行号和原因修复。需要保留的问题说明时，放入专门的排查小节或一个只描述本章最重要风险的 callout。编译成功判据、警告策略和选项职责可以写在对应代码块的原生注释中。
