# 文档内容写作

## 文件关系先于单页润色

多个页面一起修改时，先确定入口、索引和正文的职责。入口只回答“这是什么、从哪里开始”，索引只安排顺序，正文负责一个可完成的任务。前置页面不提前展开后续命令，正文不重复索引给出的路线。

包含实际源码和构建结构的章节，应在第一次展示源码前加入目录树，展示前核对真实磁盘。目录树的操作细则见 `references/zh/chapter-writing.md`。

## 页面增长与拆页

教学页达到 150 行或 5000 有效字符后，按读者任务拆成同一 part 下的系列页，不做“上篇/中篇/下篇”式机械切分。每页只改变一个主要工程变量或回答一个可验证问题，例如“单文件 → CMake → 多文件结构 → 静态库 → 动态库”。每个新页面都登记到 `_quarto.yml`、part 索引与任务矩阵，并拥有独立的代码路径。

有效字符排除围栏代码和 `{{< include >}}` 行，完整工程源码由 `code/` 单独维护。长代码不得以内联围栏绕过预算；先下沉为仓库示例，再在页面中按真实文件名 include。

## 标题与页面角色

- 章节标题由 YAML `title:` 提供，页面内不再写同文本的 `# H1`，正文从 `##` 开始。
- `##` 与 `###` 不手填序号。`number-sections: false` 时序号只能手写，增删小节后会与目录和交叉引用不一致。
- C++ 代码块要明确区分完整示例与语法片段。完整示例必须包含所需头文件、`main` 和必要的返回路径；片段首行使用 `// 片段` 标明不能独立编译，代码块标题也应反映这种边界。
- 任务区的每个 `##` 对应一个可验证结果。只有概念或结构、没有独立验收的内容并入引言或相邻任务。
- H2/H3 的职责、下钻条件和 H4 禁止规则见 `references/quarto/basics.md` 的「章节标题约定」。只有一两句话或纯介绍内容并入相邻小节，不为了统一标题数量强行拆分。
- 标题只写读者要完成的任务，标题后的首句直接兑现承诺。
- 首页和卡片先说主题与读者会得到的结果，不堆叠 API、命令或完整提纲。
- 新手必须掌握的内容和引言说明放正文。引言用连贯段落交代动机、范围和全章路线，不重复后续任务的前置条件与完成结果。服务整页目标的背景概念放在引言中，任务标题下直接进入当前动作；前一小节的可观察结果应成为下一小节的起点。相邻短句表达同一条因果或执行链时，合并成保留清楚动作顺序的段落。代码块前交代本步目标、执行环境和预期变化，代码块后只保留必要的后续动作、结果和少量解释，避免命令前后出现一重一轻的断裂。Callout 只承载非主线、确有独立价值的风险、版本差异或可选替代；主线完成后需要补充的短解释可以放在 Callout 中，但不重复正文动作或成功判据。Callout 不用于装饰层级，也不放进引言。
- 需要失败分支时，先用 `## 常见错误` 按症状列出 `###`，再用 `## 自测问题` 承载自测题，最后以 `## 本章回顾` 收束。不设置章末集中式资料区。

## 重构与事实核对

重构默认在原文基础上进行：先读取原文件、相关引用和任务边界，再局部调整结构、表达和衔接。只有用户明确要求，或原结构无法安全修复时，才删除后重新生成。目录、文件名、版本号、命令输出和工程结构等可从磁盘获得的内容，必须先实际获取。无法确认时只写检查方法，不伪造事实。

局部删除或移动内容后必须回读切口，并为后文仍引用的动作保留“触发时机 → 状态变化及原因 → 可观察结果 → 下一步”的最短闭环。后文出现悬空的“然后、因此、此时、重启、再次”等承接时必须重写切口，不能只按表面冗余删除过渡句。

改标题等于改锚点。改完用 `run.py check --profile fast` 和 `run.py render` 核对交叉引用。

## 配置文件与 CMake

`CMakeLists.txt`、YAML 和 Dockerfile 等声明式文件使用原生注释，注释位置遵循 `references/quarto/terminal-validation.md`。CMake 术语优先采用 [CMake 官方中文文档](https://cmake.com.cn/cmake/help/latest)。

## 文档类型边界

这套“目标、解释、验证、少重复”原则也适用于 Skill 和 `.agents/knowledge/`，但它们优先保持短小、可检索和可执行。Skill 与说明文档默认使用段落、表格、编号步骤和代码块，不为凑结构加入图片或 Mermaid。只有复杂分支难以用文字表达时才例外，并在图后补充结论。

README 遵循 GitHub Markdown，可以保留 Actions、许可证徽章和有信息价值的图片。根目录 `README.md` 是在线阅读链接的唯一入口，根目录 `index.qmd` 不重复该链接。`AGENTS.md` 只保留硬性执行规则。

## 行内代码与链接

- YAML `title`、Markdown 各级标题和导航文本不使用反引号。标题中的技术名词直接写成普通文字，例如“用 CMake 构建程序”，避免导航区域混用代码字体。
- 反引号只包裹需要精确识别的技术对象：命令、工具、参数、文件名、路径、配置键、API、标识符和包名。
- 同一对象在同一章节内必须使用一致的标记方式。普通概念、平台和产品名称不自动加反引号。
- 指向仓库文件时写成可跳转链接，不用反引号包住路径冒充链接。
- 中英文之间保留空格。链接标签两侧的间距按标签内首尾字符决定，标签内不写反引号。
- 正文只保留读者当前动作必需的外链。手册、完整参数列表和上游项目文档在首次需要该资料的任务中就地链接，不设章末集中区。

写完章节后用 `run.py check --profile fast` 检查关键工具和命令是否漏标记。标记边界与间距依据运行：

```bash
& .agents/skills/agent-ops/scripts/run.ps1 kb-search "行内代码 链接间距" --domain quarto-docs
```

## 文档元素

元素选择服务于结构与可读性，不以装饰为目的。

### 代码与媒体

- 可复制示例使用 `{.语言 filename="标题"}` 属性围栏：命令标题写 `PowerShell（管理员）` 或 `Ubuntu Bash（工程根目录）`，文件内容写真实文件名，输出写 `输出`。标题只声明来源，正文只说明当前动作，不重复“这是 Bash 代码”之类环境信息。
- 图片提供 Alt 文本和说明。图表标注坐标轴与单位。
- 仓库文件使用可跳转链接。短技术标识使用行内代码。

需要“对象 → 属性”式清单时，表格列的选择与列数口径见 `references/zh/chapter-writing.md`。

### Callout 提示框

只用内置 5 类，自定义 `.callout-*` 类会被静默丢弃。语义按读者的动作选择，不按“重要程度”选择：

| 想表达 | 类型 | 典型内容 |
|---|---|---|
| 解释原理或背景 | `note` | 术语边界、为什么这样设计 |
| 更优做法或替代路径 | `tip` | 可选替代、快捷写法 |
| 风险与易错点 | `warning` | 破坏性命令、版本差异 |
| 深入机制 | `important` | 读者可跳过但不影响成功 |
| 严重且不可逆 | `caution` | 数据丢失、需要停手确认 |

带标题的 Callout 使用 `::: {.callout-note title="中文标题"}`，标题由块属性提供，块内不再写 `##` 标题。

必经步骤不进 callout。普通 callout 是块级提示，只在正文难以自然承载且读者可以安全跳过时使用。结果型 Callout 只承载下方定义的稳定结果判据，不承载动作。任务小节的块序列以 `references/zh/section-focus-and-density.md`「固定块序列」为准；补充信息使用最多一个 callout，并放在所属 `##` 或 `###` 的最后一个信息块，紧贴下一个标题之前。前后各留一个空行。不要把 callout 夹在引导段与命令、命令与输出或两个必经动作之间，也不要把它插进一个段落内部。后面仍有必经动作时，先完成这些动作，再放 callout。

参数解释默认使用短无序列表。只有参数属于可跳过的理解补充，且任务已经给出成功判据时，才把列表放进带标题的 `note` callout。读者必须据此选择或修改当前命令时，参数留在正文中。Callout 不承载必经命令或构建命令，也不把唯一成功判据写成脱离正文的脚注。

唯一例外是“结果型 Callout”：成功判据是读者会看到的稳定界面或状态，同一信息还需要拆解说明，并且其后没有必经动作时，正文先用“完成某动作后，请对照下面的格式确认结果，并了解后续范围”一类可执行检查句完成交接，再把精确判据、下一步范围和解释列表一起放进该任务末尾的 `note`。正文检查句只建立动作和目标，Callout 首句必须直接兑现该动作，不再重新起句。提示框是正文结果的延伸，不是独立插入的必经步骤。不符合这些条件时，成功判据仍留在正文。

正文与 Callout 的信息密度、列表化和重量平衡见 `references/zh/section-focus-and-density.md`「避免头重脚轻」。这里的字号只由 `quarto-theme` 维护。

### 可折叠答案

`## 自测问题` 的思考题需要自测时，答案紧跟对应列表项，使用站点级 `.answer` 组件：

```markdown
1. 问题？

   ::: {.answer}
   答案正文。
   :::
```

- 只有读者可以先自行回答、再核对结论的内容才折叠。定义、命令和必经判据留在正文。
- 答案与问题处于同一个列表项，不集中到章末，也不为每道题单独起标题。
- `.answer` 由 `.agents/skills/quarto-docs/scripts/answer-disclosure.lua` 渲染为默认收起的原生 `details.answer-disclosure`，摘要固定为“查看答案”。正文不手写这段 HTML。
- 列表型答案直接以有序列表开头时，先写一句与问题同主题的导语，交代对象、起止范围或顺序，再列出步骤。不要让列表突然承接问题。
- 答案只使用本章已经讲解的概念，内部不使用 `h1`–`h6`。

### 交叉引用

交叉引用使用真实标题生成的锚点，引用前确认目标页面存在。本项目不手写英文 `{#id}`，标题锚点由中文标题派生。手写 ID 会与中文锚点形成两套寻址方式。

需要本仓库的渲染与输出依据时，检索 `cpp-tooling-quarto-render-v2` 或 `cpp-tooling-quarto-html-v2`。
