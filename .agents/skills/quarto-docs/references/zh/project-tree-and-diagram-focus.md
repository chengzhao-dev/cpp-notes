# 工程目录树与图表主线

先阅读 `authoring.md`、`writing-style-core.md` 和 `section-focus-and-density.md`。本文件只规定工程目录树与正式 C++ 章节主线如何保持事实一致、职责清楚。取舍依据见知识库标识 `cpp-quarto-project-tree-diagram-focus-v1`。

## 目录树以实际工程为事实

- 展示目录树前先检查实际磁盘，不能凭印象添加、删除或改名。文件名保持真实大小写，统一写作 `CMakeLists.txt`。
- 目录树是教学视图，不是磁盘截图。作者可以据此排除 `.cache/`、日志、对象文件和 CMake 内部缓存等没有教学意义的暂存内容。这些筛选过程属于维护规范，不写进面向读者的正文。
- 参与项目维护的同类配置采用“全加全讲”或“全不展示”，不得只列出其中一部分。
- 本项目入门工程展示 `.vscode/`、`build/`、`.clangd`、`.clang-format`、`.clang-tidy`、`build-and-run.sh`、`CMakeLists.txt` 和 `main.cpp`。
- 展示入门工程时，根行写作 `first-program/`，并标注“示例工程根目录”，让正文中的“工程根目录”有明确落点。

## 稳定的展示顺序与注释

在实际磁盘顺序基础上，采用稳定的工程认知顺序：

1. 工程级配置目录：`.vscode/`。
2. 构建产物目录：`build/`。
3. 语言服务、格式化和静态检查配置：`.clangd`、`.clang-format`、`.clang-tidy`。
4. 自动执行脚本：`build-and-run.sh`。
5. 构建系统入口：`CMakeLists.txt`。
6. 程序源码：`main.cpp`。

首个示例工程统一使用以下行尾注释：`.vscode/` 为“VS Code 工作区配置”，`build/` 为“CMake/Ninja 构建输出目录，请勿手动修改”，`compile_commands.json` 为“供 clangd 等工具读取的编译数据库”，`build-and-run.sh` 为“配置、构建并运行程序的脚本”。其他路径使用同样的名词化结构，写明路径的用途或性质，必要时补充维护提醒。

同类隐藏配置保持相邻，不把所有带 `.` 的路径机械移到最前面。目录树是 `text` 围栏里的视觉对齐图，行尾 `#` 注释是这种图的固定写法，不受 terminal-validation「注释写在被说明命令上一行」的限制，注释列尽量对齐。树外默认不再逐项重复职责，只有当前操作确实需要时才保留一句维护与生成边界。`build/` 只展开本节需要理解的 `bin/app` 和 `compile_commands.json`。

正文在目录树前最多保留一句任务导向的过渡，例如“工程目录如下。后面的命令都在这个目录里执行。”不要写“根据实际目录筛选出的教学视图”或其他作者筛选过程。树后的职责说明已经由行尾注释承担，只有当前操作确实需要时，才补一句维护与生成边界，不再逐项复述。

目录树小节到目录树和必要的边界提醒为止。源码阅读、构建和运行分别使用新的任务标题，避免标题职责错位。

## 正式 C++ 章节不用 Mermaid 演示主线

正式 C++ 教学章节不使用 Mermaid 演示“源码 → 构建 → 运行”或其他线性主线，改用小节标题和简短因果文字衔接。只有复杂的数据流、状态转换或分支关系确实难以用文字表达时，才保留独立图表，并在图后给出一句结论。
