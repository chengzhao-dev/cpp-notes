# 工程目录树与图表主线

先阅读 `authoring.md`、`chapter-writing.md` 和 `section-focus-and-density.md`。本文件只规定工程目录树与正式 C++ 章节主线。取舍依据见知识库标识 `cpp-quarto-project-tree-diagram-focus-v1`。

## 目录树以实际工程为事实

- 展示目录树前先检查实际磁盘，不能凭印象增删或改名。文件名保持真实大小写。
- 目录树是教学视图，可以排除缓存、日志和对象文件等没有教学意义的内容，但筛选过程不写进正文。
- 参与项目维护的同类配置采用“全加全讲”或“全不展示”，不得只列其中一部分。
- 入门工程展示根行 `cmake-project/`，并标注“示例工程根目录”，让正文中的“工程根目录”有明确落点。
- 库工程的目录树必须显示库模块与 `app/` 同级，并显示库模块自己的 `CMakeLists.txt`、`include/` 和 `src/`。

## 稳定的展示顺序与注释

按“工程级配置目录 → 构建产物目录 → 工具配置 → 自动执行脚本 → 构建系统入口 → 程序源码”排列。目录树中的行尾注释说明用途或性质，必要时补充维护提醒。

树前用一句自然过渡交代文件和后续命令的位置，例如“下面的目录是本章示例的文件清单，所有命令都在该工程根目录执行。”树后只有当前操作确实需要时才补维护与生成边界，不逐项复述注释。

需要判断“哪些能改、哪些是生成物”时，在树后补一张 3 列表：路径 → 类别 → 是否手改。类别使用源码、构建配置、生成物、编辑器配置、工具配置等集合称呼，表只覆盖需要判断归属的路径。表格选型以 `chapter-writing.md` 为唯一依据。

目录树小节到目录树和必要边界为止。源码阅读、构建和运行分别使用新的任务标题。

## 正式 C++ 章节不用 Mermaid 演示主线

正式 C++ 教学章节不使用 Mermaid 演示“源码 → 构建 → 运行”或其他线性主线，改用小节标题和简短因果文字衔接。只有复杂的数据流、状态转换或分支关系难以用文字表达时，才保留独立图表，并在图后给出一句结论。
