# C++ 章节写作

先遵循 `writing-principles.md` 和 `writing-style-core.md`。本文件只规定 C++ 教学内容的组织，不替代语言语义与工具链知识。

## 环境章骨架

环境章按“建立环境 → 常见错误 → 本章回顾”收束；只有确实属于本章任务的日常工具才加入正文。安装动作作为同一任务下的 `###` 或有序步骤，不为每个工具单独开 `##`。

- 引言用普通段落建立“为什么需要 Linux 环境，WSL2 与 Ubuntu 各承担什么角色”的连贯认识；只抽象到宿主系统和发行版，不提前展开编译器、构建工具、终端或编辑器。具体系统要求、安装命令和完成结果留给对应任务，引言不放 Callout。入门章节引言控制在约 80–120 个中文字符，承接上一章并引出当前内容，不介绍章节流程。
- 安装代码块的注释密度与成功判据只在 `references/quarto/terminal-validation.md` 定义，本章骨架不复制第二套格式。
- 标题使用简短任务名，例如“安装 WSL2 和 Ubuntu”“更换软件源”“安装工具链”；限定条件和背景移到标题后的首句。常见错误的症状标题只保留核心故障，补充条件放进正文。
- 安装任务以“下一步可以继续”作为结果，不追加通用成功句；只有后续操作确实依赖某项可观察结果时，才就地给出判据。配置型环境章的本章回顾只总结环境状态并给出下一章入口，不设置思考问题。其他 C++ 章节才按需提出不超过 3 个关键问题。
- 已有官方教程的安装、版本差异、软件源写法和 GUI 配置由官方页面承接，章节只保留本项目必须执行的动作；镜像站等上游文档已经维护版本差异时，正文先说明换源只影响下载来源和速度、不改变发行版版本，再给入口、当前动作和结果；软件源命令后不追加通用成功句，也不写“本章不复制……”之类的维护说明。
- 安装其他发行版属于默认 Ubuntu 之外的可选分支。小节先说明继续使用默认 Ubuntu 时可以跳过，再按“查看候选名称 → 从输出复制名称并原样替换占位符 → 安装目标发行版”组织；这里不引入切换默认发行版的额外流程。
- WSL2/Ubuntu、可选发行版和 C++ 工具链同属环境准备阶段时，统一由 `## 准备 Linux 开发环境` 统摄，各任务使用 `###`。工具链仍有自己的命令块和可见结果，但不单独升级为 `##`。
- 常见错误放在回顾之前；标题后的首句同时说明触发条件与可观察现象，具体结构和命令写法以 `references/quarto/terminal-validation.md` 为准。

## 连续入门章节的衔接

环境章交付可继续操作的终端和工具链，首个程序章从这一状态开始，不重新讲解安装过程。两章之间只用一句承接前一章的可观察结果，并在首个程序章开头明确读者已经打开完整示例工程和进入工程根目录；未在前章提供的获取方式不能临时写成新的必经命令。

- 同一阶段的子任务使用一个 `##` 和多个 `###`：环境章按准备阶段归组，首个程序章把目录树与源码阅读归入“认识程序”，再让 `clang++` 与 `CMake` 各承担一条完整路径。
- 每个任务按“目标 → 执行位置与前置 → 最小动作 → 稳定判据 → 下一步”闭合。目录树先给工程根目录，真实源码随后出现；构建路径共享同一个源码、目标名和输出位置，读者才能比较工具而不是比较不同示例。
- 可选发行版、参数说明和构建方式选择放在主线完成后，首句明确其可跳过或适用条件。脚本属于它调用的构建路径，不构成第三种构建方式。
- 成功路径不夹入排错。配置型环境章的回顾只确认环境状态并指向下一章；首个程序章的回顾总结已获得的能力，可保留不超过三个只涉及本章内容的问题。

## 构建章骨架

构建章按“认识 Hello, World! 程序 → `clang++` 构建并运行 → `CMake` 构建并运行 → 选择构建方式 → 常见错误 → 本章回顾”展开。

- 目录树和源码阅读属于“认识程序”，可以用 `###`，但不单独升级为多个顶层任务。
- `clang++` 和 `CMake` 各承担一条可运行的构建路径，标题统一为“用某工具构建并运行”。CMake 的配置、构建和一键脚本属于同一任务。
- 构建脚本是 CMake 任务下的 `###`，不与 CMake 并列。多种构建方式的对照放在主线跑通之后。
- 各构建任务就地验证本步结果；常见错误只列本章失败分支，本章回顾用简短总结和不超过 3 个关键问题收束。
- 讲解源码到终端输出时按执行主体拆开：终端执行命令，`clang++` 编译并链接源码，操作系统加载程序，程序写入标准输出。不要用一句话压过编译、链接、加载和输出。

## C++ 示例

- 首次出现的术语给出中文名称、英文检索词和适用语言版本，后续固定称呼。
- 示例完整可运行，片段明确标出省略范围。代码注释只标记本节需要观察的行为，正文补充前置条件、因果关系、参数边界和验证信息。
- 首次通读源码时优先使用真实源码和代码注释说明关键符号；只有代码与注释仍不足以辨认读者的观察目标时，才增加符号导览。标题不放行内代码。
- 回顾使用简短总结加不超过 3 个关键问题，只使用本章已经出现的命令与文件。
- 规则型内容按“建议、理由、正例、边界、验证”呈现。
- 标准语义、复杂度、生命周期和失效规则从权威资料或项目知识库核对，不依据措辞习惯推断。
