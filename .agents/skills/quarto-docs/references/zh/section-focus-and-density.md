# 小节主线与信息密度

先遵循 `writing-principles.md`、`chapter-writing.md` 和 `authoring.md`。本文件只规定一个小节如何突出主线。领域事实与取舍依据见知识库标识 `cpp-quarto-section-focus-density-v1`。

## 一个小节只交付一个结果

- 任务型 `##` 承载一个可验证结果。多个 `###` 共享同一阶段、环境或产物时，可以让父级 `##` 统摄，但父标题必须写清阶段或范围，子标题仍各自只承担一个任务。
- 标题后的第一句直接说明目标、动作和成功判据，不先铺开背景或参数百科。
- 一节默认只保留一条主操作路径。第二条路径必须明确标为替代方案或迁移路径。

## 固定块序列

按“主线目标 → 最小动作 → 可见结果 → 一句收束 → 必要解释 → 延伸与边界”组织内容。

命令块、说明段与 `text` 输出块的顺序和写法，以 `references/quarto/terminal-validation.md` 为唯一细则。目标、命令和成功判据各有一个唯一表达位置：引言只承诺结果，操作小节给出命令与验收，脚本说明和回顾只补充新增信息。相邻段落不要重复同一构建闭环或输出。

## 避免头轻脚重

任务块不能只在开头给一句抽象目标，再在末尾连续堆参数、边界和手册链接。首句要点名执行位置、动作和预期结果，随后按“最小动作 → 输出或成功判据 → 一句收束 → 可选解释”闭合。参数或边界属于可跳过的理解层时，最多在小节末尾放一个同职责的 callout，并保证它是该任务的最后一个信息块。仍有独立动作时拆成新的 `###`，不要把说明压缩成脚注式尾巴。

## 避免头重脚轻

正文包含多个状态节点时，不为追求连贯而把账号创建、正常现象、成功判据和后续范围全部压成一个长段。主线按状态切换拆成 2 至 3 个短段，让动作、观察结果和下一步各有清晰落点。

尾置 Callout 不是脚注。它有多个并列字段时使用短列表，不把可自然展开的说明压成一句。正文与 Callout 正文字号相同，标题可以小一级但保持加粗，视觉区分交给浅底和左色条。不得为了平衡重量把必经动作移入 Callout，也不得让成功判据脱离正文动作成为孤立提示。

成功判据本身是需要拆解的稳定界面，并且其后没有必经动作时，可以使用“结果型 Callout”：正文用“完成动作后，请对照下面的格式确认结果，并了解后续范围”一类检查句交接，Callout 首句直接兑现该检查动作，再列解释。此时判据与解释同框，是为了避免正文重复和尾部拖长。标题必须同时概括判据与解释范围，正文不得再复制判据全文。预告句只建立检查动作、观察目标和使用范围，不得写“含义和范围如下”后再让 Callout 从“出现……”另起句。不符合这些条件时，成功判据和执行范围仍留在正文。

## 长段拆分与 Callout 下沉

- 判断依据是信息职责，不是固定字符数。一个段落同时承担两个以上独立动作，或把主线动作、成功判据和可跳过说明压在一起时，应拆分。
- 主线动作、必要选择、成功判据、执行位置和下一步保留在正文。优先拆成 2 至 3 个短段落，每段只承担一种职责。
- 只有跳过也不影响首次成功和验收的细节才下沉到 Callout。同一状态不能在正文和 Callout 重复。
- 提示符界面按“操作与正常现象 → 检查提示符”和“精确判据与后续范围 → 可跳过的符号含义”分层。前一层留在正文。后一组信息满足结果型 Callout 的全部条件时，可以合并为任务末尾的同一个 `note`，并由正文检查句与 Callout 首句连续接力。
- Callout 的块级位置、数量和参数落点以 `references/quarto/authoring.md` 为唯一出处。必经命令、仍需据此继续操作的判据和会影响当前操作的风险留在正文。
- 不为拆段而制造孤立短句。相邻句子仍在说明同一对象和同一结论时，应合并为一个段落。
- 同一状态内部的账号创建和正常现象可以合并。成功判据与执行范围进入下一个状态时另起一段，即使它们仍属于同一次首次启动流程。
- 段落是否过长不设自动字符阈值。代码块、行内标识和必要条件会改变视觉长度，判断仍由人工结合任务职责完成。

## 细节的放置方式

- 参数解释采用“参数 → 当前作用”的无序列表，一项只说一个参数，不展开完整选项百科。
- 省略后果只在读者当前这一步就会踩到时才补，其余选项的代价留到 `常见错误`。
- 参数解释是否留在正文由当前动作是否依赖它决定，块级写法见 `references/quarto/authoring.md`。
- 重点和次要细节优先用正文和列表区分，不为“重点”“细节”“说明”增加新的 `###`。表格、Callout 和排错层级分别见 `chapter-writing.md`、`references/quarto/authoring.md` 与 `references/quarto/terminal-validation.md`。
- 运行一次“删去测试”：删除某段后若不影响首次成功和验收，就把它后置、压缩或移出本节。
- 主线正文不超过 3 个短段落，主线代码和输出各不超过 1 块。超出时必须说明其独立任务，或移入延伸区域。
- 一个段落点名的文件或路径标识不超过 2 个，保留影响当前决策的那一个，其余用集合称呼。
- 已明确对象名称时直接复用。脚本服务于当前构建任务时，应作为该任务的三级小节。
