# 小节主线与信息密度

先遵循 `writing-principles.md`、`writing-style-core.md` 和 `authoring.md`。本文件只规定一个小节如何突出主线；领域事实与取舍依据见知识库标识 `cpp-quarto-section-focus-density-v1`。

## 一个小节只交付一个结果

- 一个 `##` 只承载一个可验证结果，标题要能回答“读者完成这一节后能做什么”。
- 标题后的第一句直接说明目标、动作和成功判据，不先铺开背景或参数百科。
- 一节默认只保留一条主操作路径；第二条路径必须明确标为替代方案或迁移路径。

## 固定块序列

按以下顺序组织内容：

1. **主线目标**：一句话说明本节要完成什么。
2. **最小动作**：只放完成目标所需的命令或代码。
3. **可见结果**：紧随动作给出实测输出或检查结果。
4. **一句收束**：确认本节完成，并连接下一节。
5. **必要解释**：只解释读者当前必须理解的规则。
6. **延伸与边界**：参数百科、替代方案和失败分支放入提示框或后续小节，不打断成功路径。

命令、输出、解释继续遵循三分法：命令块只放可敲内容，输出使用紧邻的 `text` 块，判断依据写在块外。

目标、命令和成功判据各有一个唯一表达位置：引言只承诺结果，操作小节给出命令与验收，脚本说明和回顾只补充新增信息。相邻段落不要重复“编译 → 链接 → 运行”或同一输出。

## 细节的放置方式

- 参数解释采用“参数 → 当前作用 → 不使用的后果”的列表，不展开完整选项百科。
- 重点和次要细节优先用正文、列表和内置 callout 区分，不为“重点”“细节”“说明”增加新的 `###`。
- 运行一次“删去测试”：删除某段后若不影响首次成功和验收，就把它后置、压缩或移出本节。
- 主线正文不超过 3 个短段落，主线代码和输出各不超过 1 块；超出时必须说明其独立任务，或移入延伸区域。
