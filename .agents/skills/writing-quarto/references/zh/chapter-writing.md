# C++ 学习轨迹笔记章节写作

先遵循 `writing-principles.md`。本文件只规定页面骨架和 C++ 教学落点。

## 读者

读者有编程基础，但可能第一次接触 Linux、C++ 工具链和工程构建。每页只解决一个任务。正文优先使用 C++20，环境以 Ubuntu 为准。

## 页面骨架

正文按下面顺序组织：

```text
引言 → 可选概览或结构 → 任务序列 → 常见错误 → 自测问题 → 本章回顾
```

- 引言承接上一页的结果，说明为什么开始、完成后能做什么，并给出全章路线；不复述标题和命令。
- 只有读者需要先看静态对象或整体结构时，才在引言后增加概览或结构小节。
- `##` 承担一个可验证阶段，`###` 只用于有独立动作或结果的子任务。
- 每个任务按“做什么 → 执行什么 → 看到什么 → 简短说明”推进。
- 常见错误按症状分 `###`，只保留新人最可能遇到的两三项。
- 自测问题紧跟常见错误，用带 `.answer` 的有序“为什么”问题检查本章的关键因果关系、阶段边界或成功判据；每章保留 0–7 道，没有高价值问题时不添加。
- 回顾确认读者获得的能力并说明下一页可使用的状态，不重复页面目录，也不再承载问题。

目录树、命令和输出必须来自实际工程。完整源码放在 `code/`，正文通过 `{{< include >}}` 引入。命令、输出和常见错误的三步写法只以 `references/quarto/terminal-validation.md` 为准。

## 内容优先级

章节出现取舍时，按下面的顺序判断，不用较低层级的格式或样式要求覆盖较高层级的教学目标：

1. 读者任务与章节边界
2. 信息顺序和渐进披露
3. 页面块与段落布局
4. 技术正确性和可验证性
5. 标题、列表、Callout 和代码块等表达形式
6. 句子精简、术语和标点
7. 视觉样式与装饰

新增内容先确定它在既有页面块序列中的位置，再写入相邻小节。修改后回读完整小节及前后切口，确认动作、结果和下一步仍然相邻。只有步骤存在先后依赖时使用有序列表；同级选项使用无序列表；连续因果解释保留为短段落。普通小节不为凑结构添加引言。一个段落只承担一个主要动作或结论，Callout 只补充辨识、边界或风险，不替代主流程。

目录树先核对磁盘，再只保留当前任务需要的文件。树前说明工程根目录，树后不逐项复述注释。线性构建流程用标题和文字说明，不用 Mermaid 代替。

## 术语门槛

- 保留编译、链接、目标、动态库等标准术语。
- 首次出现时用一句话解释，再进入命令。例如把 `RPATH` 解释成“程序内部记录的库查找位置”。
- 不解释对当前操作没有影响的内部格式。只保留判断成功所需的输出。
- 单位、ABI、JNI 等领域词只在相关背景出现，不在入门命令中堆叠。

## 页面类型

### 环境页

从上一页的状态开始，只安装后续需要的工具。给出检查命令和成功结果。常见失败只保留两条恢复路径。

### 构建页

先展示最小源码和构建规则，再配置、构建和运行。直接编译与 CMake 分开讲。首次程序的正文要说明 `main()` 后的花括号组成函数体。

### 工程页

先说明多文件解决什么问题，再展示接口、实现和入口。只解释当前用到的 CMake 命令，不提前展开所有选项。

### 库页

静态库与动态库各占一页。静态库说明代码如何进入程序，动态库说明程序运行时如何找到库文件。两页复用同一组示例源码。

### 语言基础页

先展示一个能运行的最小示例，再解释当前类型、关键字或作用域规则。每次只改变一个值、类型或作用域，并用输出、编译错误或行为变化验证结论。后续章节不重复前置示例，只保留理解当前规则所需的最短上下文。
