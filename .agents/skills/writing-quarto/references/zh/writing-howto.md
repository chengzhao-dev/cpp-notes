# 写作 how 合并：降噪规则、润色流程与小节主线
本文件迁自姊妹仓库 cpp-board-games 并合并原 writing-principles、polish-pass 与 section-focus-and-density 的可执行 how；正反例中的井字棋句子是姊妹仓库的对照案例。判定依据在知识库，冲突时以 knowledge 条文为准（工序见 `writing-spine.md`）。各节按写作工序从定任务到定版式排列。

## 何时打开

- 中文写作的最高优先规则与润色流程、小节主线 how 都在本文件；打开一条链后只读需要的 `##`；信号表见 `writing-signals.md`。依据与豁免不在此处：段/列表/衔接见标识 `cpp-quarto-paragraph-craft-v1`，润色判定与布局见标识 `cpp-quarto-chinese-quality-v1`，小节密度见标识 `cpp-quarto-section-density-v1`，对照见标识 `cpp-quarto-chinese-style-v1`。

## 定任务：先让新人完成任务

- 开篇说明读者在做什么、完成后能得到什么，不先铺陈历史与完整背景；每页只保留一条成功路径，高级选项与内部实现后置，不阻塞第一次成功。
- 保留标准术语，但首次出现时用一句白话解释；术语卡用就近的 callout 承载（写法见 `authoring.md`）。缩写先写全称。
- 禁止目录式堆砌：一句话只推进一个结果，章引言与节引言不用顿号串联多个交付物或动作。删改口诀：把清单删掉后读者仍能说出「本章成功判据」，这份清单就应下沉到对应小节。
- 页面标题和章引言只承诺一件事，且只承诺读者做完能做的一件事；承诺的用词来自上一章已经会用的词，不点后文才定义的名字。页面 title 改变时，着陆页卡片同步改为新 title 的承诺。
- 语言课禁令、否定式预告、不写「下一节」都在这一步判：它们决定本章能不能出现某句，不是措辞问题（细则见知识「句子规则」、`chapter-writing.md`「叙事范围」）。

## 定结构：信息按动作排列

每个任务按「目标 → 执行 → 结果 → 必要解释」排列：先说明这一步要解决什么；给出最少命令或操作；给出稳定、可观察的成功结果；只解释继续操作所需的细节。

任务节按「类型 → 简单函数 → 更难的函数」排列，最难的组装放在最后，并满足先定义后调用：读者要跟着读懂的标识符，其行为必须已经出现过（上一章、上文，或同一小节紧挨的声明和一句行为）；未定义名字的调用链整段删除（对照见知识 `cpp-quarto-chinese-style-v1`）。

标题按三步收成短名：先圈出目录里要扫到的对象，删掉指示（这一步、这次）、过程动词（记下、收进、用到）和数量（三种、九个），再检查同一二级下的三级标题句式是否一致；数字与形式见知识「字数硬限」，不在此复制。

失败分支放到「常见错误」。可选说明放到任务末尾，或直接删除。删除后不影响首次成功的内容，不应出现在主线。凑字数句（统计性凑句、导航复述段）一律删除；删除判据见知识「凑字数禁令」。

## 定结构：小节主线与密度

密度依据与取舍见知识 `cpp-quarto-section-density-v1`；篇幅量化兜底见知识「分层上限」。执行要点：

- 任务型 `##` 承载一个可验证结果；标题后第一句直接说明目标、动作和成功判据。`##` 承接 ≤2 句、`###` ≤1 句。
- 一节默认一条主操作路径；单个 `###` 只推进一个对象。`###` 装不下新对象时按主题拆 `##`，不硬加超出限额的第 5 个 `###`。
- 标题归并（规则在 `writing-spine.md`，判定数字在 `cpp-quarto-chapter-structure-v1`）：只负责解释下一块代码、命令或图的小节降为 `###`；短到没有独立观察步骤的内容连 `###` 也不留，并入相邻正文；一个任务型 `##` 下设 `###` 时至少两个，只有一个时删去该 `###` 的标题、正文归回 `##`，或补出真正独立的同级小节。固定收尾「常见错误」「自测问题」「本章回顾」不参与归并，症状 `###` 照常保留。
- 固定块序列「主线目标 → 最小动作 → 可见结果 → 一句收束 → 必要解释 → 延伸与边界」；命令与输出细则见 `terminal-validation.md`。
- 相邻盒子之间必须有交代判断依据的正文；代码与图的桥接序列见 `authoring.md`。
- 避免头轻脚重与头重脚轻：首句点名执行位置、动作和预期结果；主线超一段时先规划 `###`；正文多状态节点拆 2–3 短段；尾置 Callout 保持可扫读的信息重量。
- 长段拆分按信息职责不按字数：主线动作、成功判据、执行位置留正文；只有跳过也不影响首次成功与验收的细节下沉 Callout；不为拆段制造孤立短句。
- 细节放置：参数解释「参数 → 当前作用」一项一条；主线正文不超过 3 个短段落，主线代码和输出各不超过 1 块；一个段落点名的文件或路径标识不超过 2 个。

## 定段落：衔接与句段删改口诀

一段一个对象、段间衔接、概念负荷的判定依据见知识 `cpp-quarto-paragraph-craft-v1` 对应条目；逐段删改检查清单见 `writing-signals.md`「定段落删改检查清单」，命中即改。

## 定句子：句子要短

设计说明的分句角色链（事实 → 约束 → 因此选择）见知识「句内骨架」；句序与段落形态判定见知识 `cpp-quarto-chinese-quality-v1`。

- 一句话只推进一个动作或结论。超过 40 字且包含多个动作时拆分。
- 多中心判定口诀：删掉任一分句后句子中心仍然成立，原句就是多中心句，按中心拆成两句。
- 拉链句判定口诀：删掉句中任一配对后，剩下的配对仍能单独成立，原句就是拉链句。三条改写按顺序选，停在第一条适用的：推迟（`##` 有 `###` 时按顺序点名子节，至多两句、一句一个对象，不点后文才定义的类型名）；拆句（两个成立的观察分成两句，后句用「因此 / 所以 / 接着」接住前句对象，禁用「分别交给 / 各说一层 / 分别是」）；一项一行（同一对象三项以上取值或属性进列表，一项一行）。工序链（先…再…串同一条操作）、同物两处（一个主语指声明与实现两处）、回顾收束一件能力，不按拉链改写（判定与分工见知识「拉链句」，对照见知识「拉链句」）。
- 相邻句子的因果、时序关系要写在句面上：先给依据（可观察事实、不变约束），再写因此作出的选择；违背因果即调整。
- 写完数量词和「这些」，对着下一块点名：写「四个入口」「覆盖四类」，下一块就要列出四个名字或四类场景；对不上就改成点名对象（判定见知识「一次对话」，对照见知识「定句子：数量词对着下一块点名」）。
- 句子主语是工程对象，不用「是规则，代码把它写成」类元叙述开场；对象先行，不用标识符开句（对照见同知识「元叙述开场与对象先行」）。

## 定用词：术语要稳

- 操作使用「确认、创建、查看」等动词，不用被动句和名词化表达；「由 X 完成」改成主动句，改完露出第二个核就退回定段落。同一概念只用一个称呼，英文标识保持大小写。
- 删除「众所周知」「简单来说」「完全可以」等没有信息的修饰。禁用词以 `verify_content.py` 词表为准（脚本随批次 7 校验迁移落位）。
- 连续出现三个「的」时改写。
- 正文提及枚举类型与成员函数时写源码完整标识符（`GameResult`、`Game::TryPlace`），不设「概念简称」层；架构层名首次出现用一句可观察行为定义；讲读写路径先说屏幕上发生什么，再点名成员，最后一句边界（对照见知识「零基础可懂的读写路径与层名定义」）。
- 枚举成员的含义写在源码行尾注释里，正文不复述成释义列表或释义段；正文只写谁调用、如何验收、与邻章关系（规则见 `chapter-writing.md`「叙事范围」）。
- C++ 概念点名按知识 `cpp-teaching-chinese-terms-v1` 用词；读者侧禁用行见知识 `cpp-quarto-terminology-v1`；语域判定与口语腔、公文腔的正向标准见知识 `cpp-quarto-chinese-voice-register-v1`。

## 定版式：格式要降噪

- 命令、参数、路径、文件名和标识符使用行内代码；Ubuntu、Windows、VS Code 等平台名作普通名词时不加。
- 可复制命令使用指定语言的代码围栏，命令与输出分开。
- 标题和导航不使用行内代码。中英文之间保留空格。
- 正文不用分号；需要并列时拆成两句或改列表。正文不使用破折号夹心解释：解释用冒号引出，或拆成两句；冒号合法场合见知识「散文伪标签冒号禁令」。分号不得用来给块前导语挂 cpp-notes 外链；跨仓链默认不写，若保留须工程点后尾置「若要系统阅读…」，禁止「写法依据见」等依据句。
- 列表用于并列或顺序关系。表格只用于需要对多个属性进行比较的内容：同一主题的属性合并成一张表，不按小节拆成多张薄表；只有一两列信息或右侧大量留白时改用句子或列表。列表是版式选择，不是新的一段说明。
- Callout 只放可跳过的提示，不承载必经步骤和唯一成功判据。

具体元素写法见 `references/quarto/authoring.md`，终端步骤见 `references/quarto/terminal-validation.md`。

## 润色流程：沿着工序走

润色任务沿 `writing-spine.md` 的写作工序执行，从定任务走到过闸，跳步视为未完成；判定标准见知识 `cpp-quarto-chinese-quality-v1`。两种走法共用 1–9：**增量润色**保持最小改动，只改判废句，不做风格重塑；**全章重构**按 `writing-spine.md`「工序分层」走——章级（1–2）先定删留不动句子，节级（3–4）只拆块和段，句级（5–7）逐句拆开再写回去，该层全部重组，不走最小改动。执行时遵守定段落节的既有判定：分句骨架在定句子判废，不在定段落里顺手改句子。

**先切模块，再套规则。** 任何一步动笔前先把文本切成单位，围栏、YAML 与链接 URL 跳过（脚本按同一口径统计，计数见 `verify_content.py` 输出）：

- **章**：标题到下一个 `##` 之前。只做定任务、定结构。
- **节**：`###` 到下一标题。只做主线与标题对齐。
- **自然段**：空行隔开的散文。只做一段一中心、概念负荷、块后还有没有新信息。这一步不改分句措辞。
- **句子**：段内按「。！？」切开。只做一句一中心、拉链、句内骨架、和下一句是否互相否定。
- **列表项**：`-` 或有序编号。只做一项一中心、平行、字数带。不把列表项当散文拉链改。
- **表格单元格**：管道表。一表一事；格里写事实，不写第二篇散文。
- **块**：导语、围栏、块后、Callout。围栏不是句子。块后只保留注释和导语都没写的工程信息。

「一次对话」不与这些单位并列成切分单位：脚本切得出标题、空行、句号、列表和表格，切不出「一次说话」。它只留在知识「一次对话」的判定里——定段落先问这段有几件内容，再决定删、拆或切成几次说话；定句子才改措辞。

1. **普查建账**：`git ls-files` 按扩展名分类，列出全部含中文自然语言的文件（跳过机器生成物与二进制）。台账写 `temp/`（不入库），逐文件记「审读状态／修改数／备注」；任务结束前每行落到「已审」，无问题也记「未发现」。覆盖率由 `check --profile fast` 的「中文体检」项（`check_zh_lint.py`）背书：台账文件总数与脚本输出的载体组计数对不上即为漏审。
2. **沿工序逐篇走**：从定任务到过闸，每步只改该步判废的句子；后一步发现前一步没做完，退回那一步，不在当前步补结构。某句只在定用词失败，就不重写它的结构；某段在定句子失败，先改骨架，再让定用词看一遍。已合格的句子不重润。
3. **改写**：最小改动，只改判废句，不做风格重塑。改写不破闸：qmd 导语 token 与句数、段落篇幅、禁用词由 `verify_content.py` 把关；中文文件保持 UTF-8 无 BOM、LF。代码围栏与源码注释同源：改源码注释前先 grep 各 qmd 围栏，被逐字引用的两侧同改；同源复制文件改一处同步其余并 diff 比对。改动触及知识库案例引用句时先 grep 案例文件再同步。
4. **验收同步**：按改动域跑校验（qmd → `verify --changed` + `check --profile fast`；Python → `python` profile；知识库 → `kb-index`/`kb-check`/`kb-eval`；跨域收口 `full`）。闸次纪律：每批一次闸、FAIL 必清、WARN 记台账、同指纹两轮停手。
