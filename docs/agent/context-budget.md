# 上下文预算实测

验证一件事：**省 token 是否以牺牲开发效果为代价**。答案是用「效果等价」硬判据衡量
（产物逐字节一致 + 全部校验一致），而不是凭感觉说「应该没影响」。

度量口径：**可喂入上下文的字节上界**（脚本侧可控、可复现）。不去测模型内部 token 数
（不可观测、且各模型分词不同）。上界下降即「重复喂大文件」的浪费归零。

成本模型（解释为什么要省这三样）：

```
总成本 ≈ 轮数 × 稳定前缀  +  每轮新增输入  +  每轮输出
```

一次真实排错会话（HTML 复制按钮/打印/favicon 三处修复）的账单：**输入 2.9 万、
输出 24.6 万、缓存命中 1465.4 万**。可见大头既不是「新读了什么」，而是
**轮数 × 前缀**（命中）与**输出**。故本轮优化主攻这两项。

---

## 一、测量结果

### 1. 新增输入（作用域白名单 vs 整包读）

| 场景 | 旧：整包读参考 | 新：`scope` 白名单 | 变化 |
|---|---|---|---|
| 写 `getting-started/first-program` 一章 | 52.1 KB / 12+ 个参考文件 | 27.4 KB / 9 个文件 | **-47%** |

`scope.py` 白名单内容（可复现：`python scripts/agent/scope.py getting-started/first-program`）：
本单元 qmd + 配对代码 3 文件 + 任务单 + 路由到的 4 个 reference。
**`code/.../build/` 被排除并显式标注 HOLD**——该目录含 CMake 生成物（`CMakeCXXCompilerId.cpp`
里有 `int main`），误读会污染示例校验。

| 项 | 旧流程 | 新流程 |
|---|---|---|
| 为校验而读入 `_book` HTML | 150.3 KB（每轮重付） | **0**（由脚本内部消化，只回结论） |

### 2. 轮数（最大乘数）

| 证据 | 数值 |
|---|---|
| 上述真实会话中因 PowerShell 引号/GBK 失败的探测命令 | **≥10 次**（每次 = 一整轮「前缀 + 输出」双输） |
| 一次完整校验所需命令轮次 | 6 → **1**（`run.py check` 批处理 layout/callouts/dom/ascii/links/size） |
| 一次任务的目录枚举轮次 | 多次 `dir /s` → **1**（`run.py scope` 一次定边界） |

对策：`run.py` 用 Python `subprocess` 直调（输出按 bytes 手工解码），**不经 PowerShell 解析**，
并把 WSL 路径转换、解释器解析、`--book-dir` 参数固化进去。

### 3. 输出侧（terse 分级）

| 项 | terse（默认） | `--verbose` |
|---|---|---|
| `run.py check` 输出 | **1 行 / 28 字节** | 7 行 / 304 字节 |
| `run.py verify` 输出 | 结论行（压掉逐文件 compile 流水） | 全量 |

规则：**给模型自读的中间结果极 terse；给人看的结论与验收保持清晰**。
过度 terse 会伤推理可见性，故失败时才自动展开末尾若干行。

### 4. 稳定前缀（每轮重读的基数）

| 文件 | 行数 | 字节 |
|---|---|---|
| `AGENTS.md`（L0） | 63 → **36** | 2600 → **2789** |
| 4 × `SKILL.md`（L1） | 137 → **137** | **5946** |
| `_CATALOG.md`（索引） | — | 2926 |

**诚实记录（负面发现）**：AGENTS.md 行数降 43%，**字节却略升**。原因是中文一行可密可疏，
只按「行数」定预算会被密集长行绕过；而真正决定成本的是字符量。
已把护栏升级为**行 + 字节双维度**并自证有效（见下）。
另：`_CATALOG.md` 是**新增开销**，其价值是让作用域解析与「该读哪份参考」一次确定，
避免因不知道存在而漏读（降质）或整包多读（更费 token）——它属于「花小钱买路由准确」。

### 5. 子代理隔离（杠杆 B）实测

同一侦察问题：「`theme/assets/favicon.svg` 被仓库哪些文件引用？」

| 做法 | 进入主线程上下文 | 2.69 MB 扫描发生在哪 |
|---|---|---|
| 主线程直接 `git grep` | **15 行命中**（≈2.5 KB），且此后**每轮继续重付** | 主线程 |
| 派子代理侦察 | **约 150 字摘要**（≈0.4 KB） | 子代理自身上下文，主线程不见 |

结论：子代理省下的是「命中行 × 后续所有轮次」，在其首次成功即回本。
**阈值判据**（已写入 `AGENTS.md`）：预计读 >8 文件或需全仓检索才派；≤3 文件本地直读更省
（省掉子代理启动与整合开销）；编辑类任务不派（改动须回主线程）。

## 三、残余天花板（别指望继续压的东西）

- **系统注入块**（含 4 个 skill 的 `description`）每轮固定，是降不掉的地板；
  仓库侧只能压 L0/L1 与按需读取，命中不会归零。
- **子代理有启动/整合开销**，只在探索密集时净省；阈值判据不严格执行反而会 +轮次。
- **中文文档的体积必须按字节管**，只按行数会被绕过（本轮已踩过并在护栏修正）。
- 断言网覆盖的是**已知**契约；新类型问题仍需开逃生舱，跑完要把结论回写成新断言——
  「经验只沉淀一次」是这套机制不退化的前提。

## 四、日常执行清单（把结论变成习惯）

1. `run.py scope <part>/<chapter>` → 只读 UNIT+READ。
2. 干活；需要校验时 `run.py check`（1 轮），渲染用 `run.py render`。
3. 侦察类「读很多、只要一句结论」→ 按阈值派子代理。
4. 断言 FAIL 或新症状 → 一句声明开诊断模式 → 查完回写成断言。
5. 会话中途尽量**不动靠前的 L0/L1 文件**（改动会使其后全部内容缓存失效）。
