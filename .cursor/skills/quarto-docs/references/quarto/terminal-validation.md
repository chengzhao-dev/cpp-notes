# 终端命令与实测输出

## 命令与结果的顺序

命令块前分别说明执行环境和前置条件，不把权限、系统版本、命令和结果挤在同一句中。推荐使用以下顺序：

1. 说明先决条件和执行位置。
2. 给出可复制的命令。
3. 展示预期结果或真实输出。
4. 说明成功判据和下一步。

有明确先后关系的动作使用有序列表；并列的系统要求、工具要求和注意事项使用无序列表。

## 实测输出

目录、文件名、版本号、工具状态和终端输出应先通过磁盘或命令获取，再写入文档。标记为在 Ubuntu 或 WSL 中运行的只读验证命令，先实际执行，再保留能判断成功的关键行。输出过长时可以筛选版本行、状态行或关键错误，但不能凭空编写结果。

安装、升级和转换发行版等会改变系统状态的命令只展示操作步骤，不在写作过程中重复执行；安装完成后的版本检查可以单独实测并展示结果。环境不可用时只写检查方法，并明确没有实测输出。

不预先编写长段环境校验。逐项运行 `g++ --version`、`cmake --version`、`wsl --status` 之类命令只能证明「此刻命令可调用」，读者已经安装的软件包不会因此变可靠，一旦环境缺失还得重读一遍诊断流程，收益低于成本。安装命令之后直接进入下一步实际操作，报错时由 FAQ 承接诊断。

需要展示工具版本时，把版本信息作为一次实测输出的副产品（例如配置阶段打印的编译器版本），不单独铺陈多条版本命令。

## 诊断与代码块

常见问题中，如果多个命令需要按顺序执行或需要读者复制，使用命令块；一两条无需上下文的短命令直接放入正文。Linux/WSL 命令使用 `bash`，Windows PowerShell 命令使用 `powershell`；真实输出使用紧跟命令块的 `text` 代码块。

删除、重建和重新配置分开表达；“某操作不会影响哪些源文件”这类短结论可以使用 Markdown 引用块。命令块只保留可复制命令，结果、成功判据和下一步不要在正文中重复堆叠。

每个代码块前说明目的，后说明成功判据或下一步。命令输出与命令放在同一个代码块中，并用当前语言注释标出输出区域；代码块中的注释只说明当前操作的职责，不逐行翻译命令，也不引入正文没有讲过的概念。

正文只做简短引导；命令用途和判断重点优先放在代码块中的原生注释里，避免同一命令在正文和代码块中重复解释。执行环境写在代码块前。命令与结果保留在同一个代码块中，代码块后的正文只保留成功判据和下一步。
