# 文档元素：图表、表格、Callout、FAQ 与交叉引用

## 选择合适的展示方式

先判断读者此刻要完成的动作，再选择元素。元素服务于理解，不用于填充页面；一个代码块、表格或 Callout 只承担一个主要目的。实际代码优先采用“最小示例 → 一个变化点 → 行为或输出 → 验证”的闭环。

涉及实际工程结构时，先用目录查看命令获取真实的目录和文件列表，再决定是否展示目录树。目录树从根目录开始，按真实层级自上而下排列，只保留当前任务需要理解的源码、构建文件和关键生成结果；不要凭想象补充文件，也不要展示缓存、日志、对象文件或其他 CMake 杂项。

目录树优先使用 `text` 代码块，以保留层级关系。行尾注释只写简短职责，不依赖空格精确对齐；较长解释放在代码块后。代码块前说明读者为什么需要看结构，代码块后明确下一步从哪个文件开始。修改工程结构后，同时核对目录树、代码块、构建命令和输出文件名称。

| 内容 | 推荐形式 |
|---|---|
| 名称、用途和对比关系 | 表格 |
| 有明确先后顺序的操作 | 编号列表 |
| 规则、风险和易忘事项 | Callout |
| 多个对象之间的流程或关系 | Mermaid 图 |
| 实际代码工程的文件关系 | `text` 代码块目录树 |
| 代码已经表达的内容 | 不再用列表重复说明 |

每个元素只承担一个主要目的。先用正文说明读者要判断什么，再给表格、列表或代码；展示后用一句话说明结果与下一步。代码块不能孤立出现，代码块前要交代执行环境或用途，代码块后要说明成功判据或下一步。

命令块中已经有用途注释时，正文只保留执行环境和简短引导，不再逐句复述命令作用。命令块展示可复制操作，`text` 块展示命令与关键输出；不要用一段长正文同时解释多个命令。

引用块使用 Markdown `>` 承载短提示、边界条件或不改变主流程的结论。一个引用块只表达一个判断，不替代正文步骤、命令块或 Callout；技术名称保留必要的反引号，较长解释移回正文。引用块的颜色和边框使用主题令牌，确保亮色、暗色和窄屏下都可读。

目录树只用于包含实际代码、构建文件或可验证工程结构的章节。它应依据真实目录从根目录开始自上而下排列，并保持源码、构建配置、构建脚本、关键生成结果的阅读顺序。使用 `text` 代码块保留树形路径，可在行尾添加一条简短职责注释；注释较长时放到代码块后的说明中，不依赖空格模拟对齐。只展示读者当前需要的文件，不展示缓存、日志、对象文件或其他 CMake 杂项；目录树前说明用途，目录树后衔接下一步要阅读的文件。目录树中的注释只说明当前页面会使用的职责，不解释页面没有展开的工具或插件机制。

首页卡片同样只承担一个主要目的。标题说明主题，描述说明范围和学习结果；卡片正文保持短小，不展开具体命令、API 或实现步骤。

## 表格

表格用于并列比较，不用于承载长段落。表头使用读者能直接理解的名称，单元格保持短句；技术名称、命令、文件名和状态值可以使用反引号，完整解释应拆回正文。不要把整句或普通概念全部包进反引号。

短表格可以使用列对齐标记和专用容器居中显示；列内容较少时不要让整张表被无意义地拉伸。宽表仍保持左对齐和横向滚动，优先保证可读性。

代码块不承担表格排版。代码、命令和终端输出统一左对齐并保留源码缩进；需要对齐名称、用途或字段时使用表格。

## Mermaid

流程或关系图使用 Quarto 的 ```` ```{mermaid} ```` 围栏。按步骤推进的流程默认使用纵向 `flowchart TD`，只有横向分支比较更清晰时才使用 `LR`。图前说明读者需要观察的关系，图后用一句话总结结论；不要同时把同一流程重复为列表。渲染后应出现 SVG 图形，而不是普通代码块。

## Callout 提示框

只使用 Quarto 内置的 `note`、`tip`、`warning`、`important` 和 `caution` 五类。Callout 使用全局配置的中文类型标题，不在块内再写标题；前后各留空行：

```markdown
::: {.callout-warning}
请先确认工具版本，再继续后续步骤。
:::
```

建议、背景说明和进阶补充分别映射到最贴切的内置类型，不创建自定义 `.callout-*` 类，也不用“最佳实践”“关键洞察”“深入”等额外标题。

## 代码、列表与交叉引用

命令、关键输出和成功判据按“先决条件 → 命令 → 结果 → 下一步”排列。简单版本命令直接展示完整命令；输出只保留判断所需的关键行，不为截短输出额外引入未讲过的管道。只读验证命令应展示真实且经过筛选的结果；安装或升级命令只展示操作，不补写未实际执行的输出。常见问题需要多个动作时使用代码块，不把诊断命令塞进一段长句。

前置条件与操作步骤分别表达。系统要求、权限、版本和工具状态等并列信息使用无序列表；安装、配置和验证等有先后关系的动作使用有序列表。列表前说明读者需要判断什么，列表后衔接命令或结果，避免把一长句拆成没有逻辑的短句。涉及可由磁盘或命令获得的文件结构、版本号和终端输出时，先实际读取或执行，再编写展示内容；无法确认时只写检查方法，不伪造结果。

有先后关系的动作使用编号列表；不要把代码块中已有的命令再次逐条复制成列表。列表项中的反引号只标记需要原样输入或识别的技术对象，说明文字保持普通正文。代码块中的重要行在正上方使用语言原生注释，注释解释当前章节的学习重点。

交叉引用使用稳定标签和 `@sec-`、`@tbl-`、`@fig-` 语法。引用只补充阅读路径，不替代当前小节对结论的说明。

只有一两条且无需上下文的短命令直接写在正文中；有顺序或需要比较用途的命令才使用代码块。代码块中重要命令的注释放在命令上方，代码块外再解释原因和判断标准。命令输出使用 `text` 代码块，与其他代码块共享 GitHub 风格的视觉布局和复制功能。

## FAQ 与章末

FAQ 只收录读者完成主流程后仍可能遇到的阻塞问题，每个问题给出原因、判断方法和最短修复路径。章节末尾依次保留回顾、下一步和必要资源，避免重复正文。
