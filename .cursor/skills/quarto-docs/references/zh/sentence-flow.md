# 中文句子与段落衔接

本文件补充 `writing-style-core.md`，专门处理中文技术文档的句间关系、段落拆分和新手阅读节奏。写正文时遇到“意思都对，但读起来跳跃”的问题，读取本文件。

## 一个段落只推进一个动作

段落先确定对象，再写动作，最后给出结果。对象不要在段落中途无提示地更换；如果必须更换，先用一句话完成过渡。

推荐顺序：

```text
当前对象 → 当前条件 → 要执行的动作 → 可观察结果 → 下一步
```

例如，说明编译时，先指出当前文件和终端位置，再给出命令，随后说明生成了什么文件。不要在同一段中同时介绍编译器选项、CMake 目标和编辑器配置。

## 连接词要表达真实关系

连接词不是装饰。使用前先判断两句话的关系：

| 关系 | 可用表达 | 写作要求 |
|---|---|---|
| 因果 | 因为、因此、所以 | 后句必须是前句导致的结果 |
| 时序 | 完成后、此时、接着 | 前一个动作必须已经结束 |
| 转折 | 不过、但是、然而 | 后句需要修正或限制前句 |
| 选择 | 如果、否则、也可以 | 明确条件和分支结果 |
| 收束 | 因此，这说明 | 回到本节正在解决的问题 |

不要连续使用“首先、其次、然后、最后”替代逻辑。若步骤之间没有因果，只按动作顺序写即可；若存在判断条件，应直接写出条件。

## 长句拆分

一句话出现三个以上动作、多个“并且”或多个括号时，优先拆成两到三句。拆分后保留同一个主语或明确承接对象，避免每句都重新介绍背景。

较长的句子通常可以按以下方式改写：

```text
原句：在完成 A 后通过 B 使用 C，并根据 D 判断 E，最后再处理 F。

改写：完成 A。接着使用 B 执行 C。
根据 D 检查结果。如果条件满足，再处理 F。
```

改写不等于把一句话机械切成多句。每个新句子都应有独立信息，句子之间用真实的条件或时序关系连接。

## 代码块前后要闭环

代码块前回答“为什么现在要运行它”，代码块后回答“看到什么才算成功”。如果还有下一步，最后一句说明下一步使用哪个文件或命令。

```text
代码块前：在 Ubuntu 中进入示例目录，准备编译 main.cpp。
代码块：给出可复制命令。
代码块后：命令成功后会生成 build/bin/app，下一步运行它。
```

代码已经表达的参数不在正文中逐项翻译。正文只补充执行环境、成功判据和读者容易误判的边界。

长句按“场景 → 操作 → 结果”拆分；边界条件放在动作之前。简短且不改变主流程的结论可使用引用块，避免正文同时复述命令、条件和结论。每个段落只保留一个中心判断。

## 中性表达与承诺边界

页面只展示操作时，使用“查看、创建、编译、运行、验证、生成”等动词。不要把示例提升为没有后文支撑的理论承诺，例如“彻底理解”“解释所有原因”或“掌握内部机制”。

如果当前页面没有展开一个概念，使用“本节暂不展开”或把内容移到后续页面，而不是用一句注释留下未兑现的解释任务。

## 面向新手的术语节奏

一个段落最多引入一个新的工具或概念。首次出现时给出中文名称和英文检索词，随后固定称呼。例如先写“构建系统（build system）”，后文统一写“构建系统”，只有在命令、文件名或搜索入口中才使用英文形式。

不要在同一句中同时引入 Windows、WSL2、Ubuntu、VS Code 和 CMake。按实际操作顺序分段介绍：先说明 Windows 与 WSL2 上 Ubuntu 的关系，再说明 Ubuntu 中的工具，最后介绍编辑器如何打开项目。

## 反面案例与修正

### 概念、命令和排错混在一起

反面案例是先解释工具职责，马上给出多组命令，再插入配置文件，最后回到安装步骤。读者无法判断当前命令的目标。

修正为“目标 → 条件 → 一组命令 → 成功判据”，完成后再进入下一组操作。排错单独放在主流程之后，并引用主流程中的命令和结果。

### 用注释代替正文

代码注释只说明读者需要观察的代码行。不要把未在正文出现的比较、性能结论或语言原理塞进注释；需要解释时放在代码块前后，并确认本节确实提供了证据。

### 为了完整而提前扩展

高级配置、插件界面、发布选项和其他构建后端不影响首次成功运行时，不放入主流程。可以在章节末尾给出官方链接，但不要把它们伪装成当前任务的必要步骤。

## 多文件协作检查

同时修改 README、索引页和正文时，按下面顺序复核：

1. README 是否只保留入口和最短路径。
2. 索引页是否只安排学习顺序。
3. 正文是否完成一个独立任务。
4. 前置页面是否没有提前展开正文细节。
5. 下一步链接、文件名、命令和术语是否一致。

完成单页润色后，再从入口顺读到正文。单页内部通顺不代表多页之间没有重复或跳跃。

## 交稿前快速检查

- 标题后的第一句是否直接兑现标题。
- 每个命令块前是否说明目的。
- 每个命令块后是否说明成功结果。
- 长段落是否可以按对象、动作、结果拆分。
- 连接词是否表达真实的因果、时序或转折。
- 是否承诺了页面没有实际说明的内容。
- 新手是否能判断当前在哪个终端、操作哪个目录。
