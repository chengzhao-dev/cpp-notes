# 中文写作核心规范（cpp-notes）

## 目标

面向初学者解释概念，同时为熟悉 C++ 的读者保留准确术语、判断标准和可继续查阅的入口。先说结论或目标，再解释原因，最后给出操作与验证。

## 段落与衔接

- 每段只承担一个中心意思，通常先主题句，再解释、例子或限制。
- 用“因为/因此”表达因果，用“不过/但是”表达边界，用“完成后/此时”表达步骤结果。
- 首次出现的术语给出中文名和英文名，后续统一使用一种称呼。
- 把必须记忆的规则写入正文，把风险和易忘事项放入 Callout。
- 避免把同一命令同时写进正文、列表和代码块；代码块负责可复制，正文负责理解。
- 代码块前交代执行环境或用途，代码块后说明结果、成功判据和下一步；不要让代码块成为与上下文割裂的孤立片段。
- 句子按“目标 → 原因或条件 → 动作 → 结果”推进；后一句应承接前一句的对象或结论。面向新人时，一次只引入一个新术语，并在操作前说明成功判据。

## 标题层级

长 `##` 按“概念 → 操作 → 验证 → 排查”加入必要的 `###`；短内容保持单层结构。标题应描述读者要完成的任务或获得的认识，不用空泛的“相关内容”。

- `###` 必须对应独立的学习任务、代码示例、验证步骤或排查流程。
- 只有一两句话且没有独立示例、列表或判断标准的内容，合并到相邻小节，不单独设标题。
- 合并后让段落直接承接前一段，避免为了保持标题数量均衡而拆分内容。
- `##` 下只有引言、两三项并列内容或短列表时，不另起 `###`；把这些内容并入 `##` 的开篇段落。
- 索引页的 `##` 用于分组，不为了制造视觉分隔重复增加短小标题；单卡片仍沿用与双卡片相同的网格节奏。

## 标题与首段一体

标题和紧随其后的首段是一个阅读单元：首句必须兑现标题承诺的结论或动作，不要用标题已经暗示的背景信息垫开答案。例如标题是「build 目录能删吗」，首句先写「可以」以及可否删除的核心理由（产物可重建、不丢源码），细节和步骤放在后面；不要先铺陈目录里有什么、却迟迟不回答能不能删。

## 首页与卡片文案

- `title` 负责说明页面身份；`description` 负责交代范围、目标和读者收益，控制在一到两句。
- 卡片标题使用自然语言，直接说出主题，不在标题中使用反引号。
- 卡片描述只保留主题和学习结果，通常写一到两句，不罗列 API、命令或完整章节提纲。
- 只有读者需要原样输入、搜索或区分的技术对象才使用反引号；普通概念和整句说明使用正文样式。
- 同一组卡片使用相近的句式和信息密度，避免一张卡介绍目标、另一张卡罗列实现细节。

## 长章节与展示方式

- 名称、用途和差异使用短表格。
- 有顺序的操作使用编号列表。
- 流程和关系使用 Mermaid。
- 规则、风险和关键提醒使用内置 Callout。
- 同性质的命令输出最多展示三组，其余用文字说明验证方法。
- 列表项写成可独立理解的短句，尽量保持相邻项的信息密度和行长接近；不要让一个只有几个字的中间项打断阅读节奏。
- 标题使用自然语言；反引号只标记正文中的命令、文件名、路径、选项、变量、API、状态值和短代码字面量，不放进行内代码标题。
- 反引号用于精确标识技术对象，不用于普通概念、完整句子或单纯强调；同一术语在相邻句子中不重复加反引号。
- 列表和表格优先使用普通中文说明，只有需要读者原样输入、查找或区分的技术对象才使用反引号。
- Mermaid 使用 Quarto 专用 ```` ```{mermaid} ```` 围栏，避免退化为源码展示。

内容较多时，先判断是否已经出现多个独立学习任务，再决定增加 `##` 还是 `###`。一个 `##` 不应同时容纳过多概念、操作、验证和排查；短内容不需要为了均匀而增加标题。全文按“先易后难、先行为后原理、先最小用法后限制”推进，保持前文已经介绍的术语。

开发环境说明按“宿主系统 → Linux 环境 → 编辑器 → 语言服务 → 构建工具”组织，明确 Windows、WSL2、Ubuntu、VS Code、clangd 和 CMake 各自承担的职责。

QMD 可以使用能明显帮助理解的 Mermaid 或图片；Skill 和 `docs/` 默认不用，复杂关系确有必要时才使用，并同时给出文字说明。README 保留 GitHub 徽章、图片和外部链接；`AGENTS.md` 不使用图像和 Mermaid。所有文档都优先使用完整中文句子，减少括号、破折号、斜杠和过密的解释性冒号。破折号只用于确有转折或插入语的情况，斜杠只用于固定技术写法；并列关系优先用顿号、逗号或拆成两句。

## 代码注释

代码注释解释本节真正的学习重点，不逐行翻译。首次出现且需要记忆的代码行，在它的正上方使用对应语言的原生注释；背景代码不重复注释，复杂原理放在代码块外。这里的代码注释与正文中的反引号不同：反引号只标记行内技术对象，不能替代代码块中的原生注释。代码、命令和终端输出统一左对齐并保留缩进；字段对应关系使用表格，不用空格在代码块中模拟表格。

Shell 脚本若需要整份文件的用途说明，把注释放在 shebang 之后、`set -euo pipefail` 之前；该注释说明整个脚本，不是注释下一行的 `set`。展示或收录这类脚本时保留 `set -euo pipefail`，不要为「精简」删掉。正文也不要写成「只保留某一处行内注释」，以免读者误以为文件级说明可有可无。

例如，第一章 C++ 程序可注释 `#include <iostream>`、`main` 和 `std::cout`；讲 `vector` 时只注释 `std::vector`、元素访问和迭代器等 vector 重点。CMake 术语优先参考官方中文文档，C++ 语言和标准库优先参考主流中文教材与 [cppreference 中文站](https://zh.cppreference.com/)。

## 终端命令

纯命令块不加 `$`，便于复制；命令与输出演示才使用 `$`，输出紧跟命令。代码块内不使用 Markdown 粗体、斜体或星号；注释必须符合当前语言语法。

正文中的冒号只用于简短引出，能用完整句子说明时不连续堆叠冒号。像 `wsl` 和 `wsl ~` 这样的短命令直接写进正文，不单独占用代码块。

- 命令已经表达清楚时，直接给出命令，不重复解释参数形式。例如写“运行 `wsl ~`”，不写“运行带有 `~` 参数的 `wsl ~`”。

短命令只有一两条时直接融入正文；连续命令、顺序敏感的操作或需要新手逐条辨认的命令才使用代码块。代码块内的重要命令在上一行添加简短原生注释，注释只指出该命令在本节的作用。命令与输出演示使用 `text` 代码块，不使用自定义类；它与 Bash、PowerShell、C++、CMake 代码块共享 GitHub 风格的字体和布局，但不启用语言高亮。
