# 中文写作核心规范（cpp-notes）

## 目标

面向初学者解释概念，同时为熟悉 C++ 的读者保留准确术语、判断标准和继续查阅的入口。目标是让读者沿一条可验证的路径完成任务。

## 统一教学模型

章节默认按以下顺序推进：

```text
引言 → 前置条件 → 心智模型 → 最小示例 → 逐步扩展
→ 编译或运行 → 验证 → 常见错误 → 练习或迁移 → 回顾
```

章首用一段引言承担读者收益：交代做什么、按什么顺序、完成后能用什么。每个概念先说明问题，再给规则和最小示例。规则型内容采用“建议 → 原因 → 正例 → 边界”。

## 段落与衔接

- 每段只承担一个中心意思，先主题句，再解释、例子或限制。
- 用“因为/因此”表达因果，用“不过/但是”表达边界，用“完成后/此时”表达步骤结果。
- 首次出现的术语给出中英文名，后续称呼统一。
- 必记规则写正文，风险和易忘事项放入 Callout。
- 不重复展示同一命令；代码块负责复制，正文负责理解。
- 代码块前说明环境或用途，代码块后说明结果、判据和下一步。
- 句子按“目标 → 条件 → 动作 → 结果”推进；后句承接前句对象。一次只引入一个新术语，并在操作前说明判据。
- 全文按“引言 → 前置条件 → 概念 → 示例 → 操作 → 验证 → 排错 → 回顾”递进，不在环境、原理和排错之间跳转。
- 多文件润色先确定章节关系，再统一术语、命令、链接和详略。
- 每个新术语先给中文名称和英文检索词，后续固定一种称呼；版本相关特性标注 C++ 标准版本。
- 标准语义、复杂度、生命周期和失效规则必须交叉核对；中文资料用于表达，不能替代标准语义判断。

### 句子衔接

- 每段先承接上一段的对象或结果，再引入一个新动作或概念。
- 命令前说明目的，命令后说明成功判据和下一步。
- “因此”“不过”“完成后”等连接词必须对应真实的因果、转折或时序。
- 长句按“对象 → 条件 → 动作 → 结果”拆分；不要用连续的“首先、其次、然后、最后”代替逻辑。

### 反面案例：环境说明缺少次序

下面这些做法会增加新人的认知负担：

- 开篇同时介绍 Windows、WSL、Ubuntu、VS Code、clangd、CMake、脚手架和配置文件。
- 连续堆叠大量命令，却没有说明每组命令的目标和成功判据。
- 把暂时用不到的高级配置与首次运行所需步骤混在一起。
- 在安装、工具职责、验证和排错之间反复切换。
- 装完工具链后连跑多条 `--version` 预检环境，再在 FAQ 里重复一遍同样的命令（原因见 `terminal-validation.md`）。

改进时先保证最小成功路径，再补充解释和排查入口。环境章节采用“Windows → WSL2 上的 Ubuntu → 编辑器 → 构建工具”的顺序。

## 参考资料的使用边界

LearnCpp 用于章节粒度、练习和渐进披露；C++ Primer 用于概念模型和术语；Stroustrup 用于语言、库和设计取舍的整体联系；Effective C++ 用于“建议—理由—边界”；C++ Core Guidelines 用于接口、所有权和资源管理；cppreference 与 ISO 标准用于语义精度；CMake 官方教程用于目标导向的构建流程；Google 指南用于代码可读性。中文 cppreference 和 CMake 中文文档用于译名与阅读入口。只提炼方法和术语，不复制外部原文或示例。

## 标题层级

长 `##` 按“概念 → 操作 → 验证 → 排查”加入必要的 `###`；短内容保持单层结构。标题应描述读者要完成的任务或获得的认识，不用空泛的“相关内容”。

- `###` 必须对应独立的学习任务、代码示例、验证步骤或排查流程。
- 只有一两句话且没有独立示例、列表或判断标准的内容，合并到相邻小节，不单独设标题。
- `##` 下只有引言、两三项并列内容或短列表时，不另起 `###`；把这些内容并入 `##` 的开篇段落。

## 标题与首段一体

标题后的首句必须兑现标题承诺的结论或动作，不先铺陈背景。

## 首页与卡片文案

- `title` 负责说明页面身份；`description` 负责交代范围、目标和读者收益，控制在一到两句。
- 个人项目使用“中文 C++ 笔记”或“个人学习笔记”等准确称呼，不使用暗示官方性质的“中文教程”。
- 首页或 README 先说明项目，再引出在线阅读；学习顺序和资料来源另行说明。
- 阅读路线按 part 分组，每组内部从 1 开始编号；新增 part 时追加同名小节，不跨 part 连续编号。
- 在线阅读链接只放在根目录 `README.md`；根目录 `index.qmd` 的 `description:` 负责融合项目定位、读者对象和学习范围，正文不重复站点链接。
- 卡片标题使用自然语言，直接说出主题，不在标题中使用反引号。
- 卡片描述只保留主题和学习结果，通常写一到两句，不罗列 API、命令或完整章节提纲。
- 只有读者需要原样输入、搜索或区分的技术对象才使用反引号；普通概念和整句说明使用正文样式。
- 同组卡片保持句式和信息密度一致。

## 长章节与展示方式

- 名称、用途和差异使用短表格。
- 目录树只在有实际源码或工程结构时展示，且必须先用命令查看真实目录；从根目录按真实层级自上而下排列，不能凭想象补文件。
- 目录树放在第一次展示源码前，使用 `text` 代码块保留层级；行尾注释只写一条简短职责。只展示当前需要的源码、构建文件和关键产物，不展示缓存与 CMake 杂项。
- 目录树必须与代码块、构建命令和生成结果一致；目录树前说明用途，结束后明确下一步文件。
- 修改工程结构后，同时检查目录树、代码块、构建命令和生成结果的名称是否一致。README 只承担项目入口和使用说明。
- 仓库结构说明优先写进目录树行尾注释：`content/` 保存章节正文、`code/` 保存示例工程、`theme/` 负责样式与资源、`handbook/` 保存维护资料、`.cursor/` 保存 skills 与统一工具。用了行尾注释就不在树后重复逐目录解释，树外正文只补充目录之间的对应关系。必须保证注释与磁盘真实结构精确对齐。
- 有顺序的操作使用编号列表。
- 流程和关系使用 Mermaid。
- 规则、风险和关键提醒使用内置 Callout。
- 同性质的命令输出最多展示三组，其余用文字说明验证方法。
- 列表项写成短句，保持相邻项的信息密度接近。
- 标题使用自然语言；反引号只标记正文中的命令、文件名、路径、选项、变量、API、状态值和短代码字面量，不放进行内代码标题。
- - Mermaid 使用 Quarto 专用 ```` ```{mermaid} ```` 围栏，避免退化为源码展示。

内容较多时，先判断是否已经出现多个独立学习任务，再决定增加 `##` 还是 `###`。一个 `##` 不应同时容纳过多概念、操作、验证和排查；短内容不为凑结构增加标题。全文按“先易后难、先行为后原理、先最小用法后限制”推进。

开发环境说明按“Windows → WSL2 上的 Ubuntu → 编辑器 → 构建工具”组织，直接说明 Windows、Ubuntu、VS Code 和 CMake 各自承担的职责。

QMD 适当使用 Mermaid 或图片；说明文档默认不用。所有文档优先使用完整中文句子。

## 代码注释

代码注释解释本节真正的学习重点，不逐行翻译。首次出现且需要记忆的代码行，在它的正上方使用对应语言的原生注释；背景代码不重复注释，复杂原理放在代码块外。这里的代码注释与正文中的反引号不同：反引号只标记行内技术对象，不能替代代码块中的原生注释。代码、命令和终端输出统一左对齐并保留缩进；字段对应关系使用表格，不用空格在代码块中模拟表格。

Shell 脚本若需要整份文件的用途说明，把注释放在 shebang 之后、`set -euo pipefail` 之前。展示脚本时保留这条严格模式命令，不为「精简」删掉。

例如，第一章 C++ 程序只注释当前代码块需要注意的行；讲 `vector` 时再说明容器、元素访问和迭代器等本节重点。不要在注释中引入正文尚未出现的比较对象，也不要用一条注释承诺本节不会展开的原理。CMake 术语优先参考官方中文文档，C++ 语言和标准库优先参考主流中文教材与 [cppreference 中文站](https://zh.cppreference.com/)。

入门 CMake 示例只保留实际使用的配置。sanitizer 属于调试和未定义行为专题，不在入门 `CMakeLists.txt` 中保留注释掉的备用选项；需要介绍时另建独立示例，说明启用条件、验证方法和发布边界。

## 终端命令

Linux/WSL 命令使用 `bash` 代码块，用户输入行以 `$ `开头；`$ `只是提示符，不复制执行。PowerShell 命令使用 `powershell`，不添加 `$ `提示符。命令输出与命令放在同一个代码块中，用原生注释标出输出区域。代码块内不使用 Markdown 粗体、斜体或星号；注释必须符合当前语言语法。

正文中的冒号只用于简短引出，能用完整句子说明时不连续堆叠冒号。像 `wsl` 和 `wsl ~` 这样的短命令直接写进正文，不单独占用代码块。

- 命令已经表达清楚时，直接给出命令，不重复解释参数形式。例如写“运行 `wsl ~`”，不写“运行带有 `~` 参数的 `wsl ~`”。

短命令只有一两条时直接融入正文；连续命令、顺序敏感的操作或需要新手逐条辨认的命令才使用代码块。代码块内的重要命令在上一行添加简短原生注释，注释只指出该命令在本节的作用。命令与输出演示统一放在同一个 `bash`/`powershell` 代码块中，用原生注释标出输出区域，不再紧跟第二个输出代码块。面向读者的命令优先使用完整长选项，不使用难以记忆的缩写。
