# 可执行的 C++ 规则

规则型章节借鉴 Effective C++ 的条目化表达，但只使用与当前示例相关的规则，不把条目数量当作内容质量。

## 一条规则的结构

```text
建议 → 适用场景 → 原因 → 正例 → 边界或例外 → 验证
```

建议先给结论，原因解释取舍，正例落到真实代码，边界防止读者机械套用。若规则依赖性能、生命周期或异常安全，必须说明测量或判断方法。

## 常用规则主题

- 默认使用值语义；只有所有权、共享状态或性能证据要求时才引入指针。
- 资源绑定对象生命周期，优先使用 RAII；智能指针表达所有权，不是所有指针的替代品。
- 接口尽量表达不变量和修改权限，能使用 `const` 时保持准确。
- 让编译器和类型系统承担检查，不用注释掩盖可以由类型表达的约束。
- 先选择清晰的算法和数据结构，再用测量结果决定是否优化。
- 用 CMake target 表达编译要求，不把全局选项和隐含目录作为工程接口。

## 边界写法

避免“永远”“必须”“所有场景都”。改为说明默认选择、触发例外的条件和验证办法。例如，`shared_ptr` 默认不是首选；当确有共享所有权且生命周期无法由单一拥有者表达时，才讨论它的代价和循环引用风险。

## 审查问题

- 规则是否服务于一个具体问题？
- 原因是否解释了可观察的代价或收益？
- 正例是否能在仓库工具链中编译？
- 边界是否会改变读者的选择？
- 是否提供了最短验证路径？
