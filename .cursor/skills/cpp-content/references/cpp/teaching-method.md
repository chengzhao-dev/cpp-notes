# C++ 教程设计方法

本文件规定 C++ 章节如何把语言知识、可运行示例和工程判断组织成一条学习路径。它提炼 LearnCpp、C++ Primer、Stroustrup、Effective C++、C++ Core Guidelines 和 CMake 教程的共同做法，不复制任何外部原文。

## 先确定读者任务

每章先回答三个问题：

1. 读者此刻要解决什么问题？
2. 读完后能编写、修改或验证什么？
3. 哪些前置概念已经在前文出现，哪些必须现在引入？

如果无法写出可观察的结果，就先缩小主题。不要用“介绍某语法”代替学习目标。

## 统一讲解顺序

概念章按以下闭环组织：

```text
目标 → 前置条件 → 问题场景 → 心智模型 → 最小示例
→ 一个变化点 → 行为解释 → 编译或运行 → 验证
→ 常见错误 → 练习或迁移 → 小结
```

先让读者看到行为，再解释足以理解该行为的规则；不要在第一个示例前堆叠完整语言背景。每次扩展示例只引入一个主要变化，并说明输出、类型、生命周期或控制流发生了什么变化。

## 心智模型优先

语言基础优先建立值、类型、对象、作用域、生命周期和控制流之间的关系。现代 C++ 再把这些概念连接到值语义、RAII、所有权、异常安全和接口设计。语法规则必须落到一个可观察的行为或设计取舍上。

讲解标准库时，不只列出 API。至少说明用途、输入输出、复杂度、生命周期或失效规则，以及什么时候应该选择其他工具。

## 示例与练习

示例分为四类，并在正文中明确身份：

| 类型 | 用途 |
|---|---|
| 最小可运行示例 | 建立概念和验证路径 |
| 逐步扩展示例 | 展示一个变化点的影响 |
| 错误示例 | 说明诊断、未定义行为或错误设计 |
| 工程示例 | 连接源码、构建目标、命令和生成结果 |

完整示例优先引用仓库源码，片段才直接写在 QMD 中。每个示例后说明成功判据；每个练习给出任务、限制和验证方向，不只要求“自己试试”。

## 规则型内容

涉及设计判断时采用“建议 → 原因 → 正例 → 边界 → 验证”的顺序。规则必须说明适用条件和例外，避免把经验写成没有上下文的绝对命令。所有权、资源管理、异常安全和接口设计优先使用这个结构。

## 资料分工

- LearnCpp：参考章节粒度、渐进披露、练习和小结。
- C++ Primer：参考概念模型、术语和由浅入深的示例扩展。
- Stroustrup：参考语言、标准库、抽象和设计取舍的整体联系。
- Effective C++：参考短规则、理由、边界和可执行建议。
- C++ Core Guidelines：参考接口、所有权、资源和类型安全原则。
- cppreference：核对标准术语、版本、复杂度、生命周期和失效规则。
- Google C++ Style Guide：参考命名、注释、一致性和读者优先；仓库的异常策略以项目配置为准。
- CMake 官方教程：参考连续构建步骤、目标导向和成功判据。

资料只用于方法和语义校验。教程不复制外部书籍的段落、例题或长篇解释。

## 章节自检

- 开篇是否给出目标和前置条件？
- 第一个示例是否足够小且可以验证？
- 每次扩展是否只有一个主要变化？
- 代码、命令、输出和解释是否相邻？
- 是否说明了边界、错误和下一步？
- 小结是否描述读者获得的能力，而不是重复目录？
